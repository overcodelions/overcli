# Changelog

All notable changes to Overcli are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Full, Swift, Turbo, and Warp response modes for every hosted backend.** Swift keeps answers concise and consolidates independent tool work; Turbo enables each backend's speed-first behavior while keeping the selected model; Warp also selects its fast-tier model (Sonnet for Claude, Luna for Codex, Flash-Lite for Gemini, and Haiku for Copilot). Color-coded icons make the ladder visible at a glance; Ollama remains manually controlled. Measured repeated-tool rounds give the next turn a targeted batching hint.
- **Detailed turn latency diagnostics.** Debug timing now separates transport readiness, first model activity, first visible text, tool execution, and answer streaming, exports every stage, and flags turns that spread the same tool across several model round trips.
- **Chronological, comparable request timelines.** Each Debug timing row visualizes actual model/tool round trips in order, including overlapping tools, and scales against the conversation's longest turn. An explicit legend explains model color, named tool colors, and the slowest-to-fastest tool ramp; balanced sheet gutters improve scanning.
- **Workers can be given errands as chats or as work.** An errand you want answered is a conversation, and an errand you want done is a run — treating both as runs meant a one-line question spun up a whole flow. User turns now keep their order in the transcript either way.
- **Distribute what is left in the pot.** Money still unspent at the end of a month can be handed to the active roster in one click, weighted by the funding priority already set, so the remainder follows the order you chose instead of sitting idle.
- **Start a conversation straight from the sidebar.** Recent grew a compose button, so beginning a new chat no longer means going somewhere else first.

### Fixed
- **Codex tool timing survives app restarts.** History replay now understands current `custom_tool_call` rollout records and preserves distinct tool calls that start within the same second.
- **Claude SDK Turbo now applies low effort.**
- **Leaving Warp restores the previous model and effort.** Full always reselects the configured backend default, so returning from Warp—or reselecting Full on an older conversation—no longer leaves the fast-tier model selected.
- **User-facing conversation and timing views no longer expose internal prompt scaffolding.** Injected batching guidance and attachment filesystem paths remain available to the model and raw Debug stream but are replaced by the user-authored text and friendly attachment labels in chat and timing rows.
- **Approval prompts survive a mid-session parameter change.** Changing a model or permission mode respawned the CLI and dropped the permission broker with it, so every tool call needing approval failed for the rest of the session. The broker is now kept registered across the relaunch.
- **Distributing what is left in the pot no longer inverts the funding order next month.** A distributed cap deliberately includes the spend already made, because a cap is a ceiling for the whole month and what matters is the headroom left under it. On the 1st the spend window resets and the cap did not, so the worker that had spent the most carried the largest ceiling into the new month — the roster you ranked last holding almost the whole pot, silently. Distributing is now what it reads as: a top-up for the month you ran it in. The budget you configured is kept and handed back on the first allocation of the next month.
- **An unattended worker stops before running shell or web tools.** `bash`, `websearch` and `webfetch` counted as local, so a worker running without permission for outside actions could execute them with no one watching. They now require the same approval as pushing or sending.

## [0.16.1] - 2026-08-24

### Added
- **A work queue as the Workers tab's front page.** The tab could say what was coming (the shift calendar), what it cost (Funds) and what it came to (the Report), and nothing at all said *now* — so it landed on whichever worker happened to be hired first, an accident of sort order standing in for a front page. The queue is banded rather than sorted, because status is not a column you order by, it is what a row is: Running now, Needs you, Finished today. A single time-ordered table buries the two rows with a decision waiting on them under eight that need nothing from anybody. Rows are items rather than batches, since you watch, unblock and read jobs one at a time; a shift that launched nothing still gets a quiet row, because that is a real outcome, and so does a worker still working out what to do, because planning is minutes of real work and a queue that stays empty while a worker is visibly thinking is lying. Where a run is in hand the run's own state decides the row, since an item's status is a mirror the orchestrator keeps and mirrors go stale — one said `running` fifteen hours after its run had finished cleanly. A benched worker's leftovers leave the page entirely: a decision "waiting on you" from someone you have already stood down is one you have implicitly made.
- **A sidebar you navigate by what you were doing.** The old list rendered where things live, and people navigate by what they were doing. **Stream** is the new layout — one newest-first list of chats, agents and runs together — and going flat costs the sense of which repo you are in, so lanes buy it back: the owner is printed once above a run of consecutive rows sharing it, never per row, and the lane you are in takes the accent rail. **Places** keeps the tree for when the question really is where something lives, chosen from a switch at the top of the sidebar or mirrored in Settings. Two layouts rather than a toggle, because they answer two different questions and a checkbox would leave people guessing what the off state does. Both render the same row components, so a run keeps its status badge, rename and guarded delete either way. Anything untouched for two days rolls up under a dashed count line in place — not hidden, which makes people hunt, and not archived, which needs a decision and an undo — with search still reaching inside it. "Active" has become **Working on**, and momentum (turns per hour, decayed) earns a row its slot past the flat touch window, so a thread you have been forty turns deep in all morning outranks a message you fired off and forgot; momentum decides membership and never the order, because ordering on history would mean something you had just started could never reach the top. The history arrows now name where they go — "Back to a flow run" — since the arrow retraces your steps and a tab click restores that tab's last place, and until it said so there was nothing on screen to tell you which one you wanted.
- **A finished run says when it left changes nobody reviewed.** A run that reached `done` looked identical whether its worktree was clean or still held uncommitted work — overcli knew the difference all along, but only inside the confirmation guard on delete, so the fact surfaced solely at the moment you tried to destroy the work. Done runs with a dirty tree now carry an amber checkmark in the sidebar and a `done · unreviewed` pill in the run pane. Only `done` is flagged: a run still running, watching or paused is expected to have a dirty tree, so saying so would say nothing. The scan is async and concurrent, because the renderer refreshes it on window focus and a blocking pass over every retained run would freeze the app on each alt-tab.
- **The local model catalogue is searchable, and its token counts survive a restart.** The catalogue was two dropdowns; it now has free-text search, a year facet and four sort orders, for a list that has grown past the point of scrolling. Usage read "Local · 32 turns · 0 tokens" because every other backend leaves a transcript that can be re-read after the app closes and Ollama has none — its counters arrive once, on the `done` frame of a streaming call, and were only ever forwarded to the live UI. They are now appended to a log as they land, one line per model round rather than per turn, since a tool-using turn makes several round-trips and each costs real tokens.
- **Create and edit sheets submit from the keyboard.** Every sheet made you reach for the mouse to finish, however short the form, and Enter — the one key everybody tries first — did nothing. Cmd-Enter now submits from anywhere, matching the composer and the file editor, and plain Enter submits from a single-line input where it has no other job. Inside a textarea both stay newline keys, and on a button or a combobox Enter belongs to whatever has focus.

### Fixed
- **An everyday project says why its history is off, and offers to fix it.** Deciding whether git works meant resolving which binary to spawn, and on macOS those differ: `/usr/bin/git` exists on a machine that has never installed the Command Line Tools, as a stub whose only behaviour is to pop the system install dialog and exit non-zero. Creating an everyday project on a fresh Mac therefore produced one with no history at all, and the sheet guessed a cause from the error text — which is how someone with no git installed was told their folder was nested inside another project. Availability is now probed before anything is spawned and the failure carries a typed reason the sheets word themselves from, with a button that runs `xcode-select --install` in a Terminal window you can watch.
- **The document pane stops showing you the last project's files.** The explorer root was global state with no owner, so it survived every conversation switch: a new chat opened with the previous project's tree beside it. It clears on a real switch, while re-selecting the same conversation and the Back/Forward arrows leave it where it was. Alongside it, three smaller lies in the same pane — a `.docx` rendered its own black body text onto the dark surface, because Quick Look's HTML declares no background and Chromium paints such subframes transparent, so the office frame now paints a white page; "Ask a question about this" returned silently for any file outside a project root, which is where all worker output lives, and now falls back to the project in context; and images, PDFs and Word files opened in the text editor, which can only render a "not editable as text" dead end with the preview one click away, so binaries open rendered unless you asked for the diff.
- **Occurrences that came due while the engine was busy are no longer written off.** An engine that walks its roster serially spends minutes inside one worker's turn, and everything behind it comes due while that turn runs — so a worker further down the roster could go a whole shift without firing. Those occurrences were not missed while overcli was closed; overcli was right here, busy. The schedule now knows the moment it was last awake and looking: anything due since then fires late, and only what predates that window is skipped. A late-but-fired item reads differently in the queue from one that was genuinely skipped.
- **Runs waiting on you age out of Working on.** A paused or watching run was kept in the section unconditionally — the intent being that a run which stopped to ask you something must not vanish, but "must not vanish" had been built as "forever", and a run left mid-flow last week sat at the top indefinitely, crowding out the work in hand. Both states now get three days rather than the flat ten minutes, because a question somebody asked you deserves more patience than a chat you wandered away from, but finite. Past that it is a backlog item, still right there in the stream with its paused badge on. A run also sits on the timeline where its work happened rather than on the day it was created, so a flow driven to step seven yesterday stops filing itself under "Earlier".
- **Dead work leaves the queue.** A paused item whose run file is gone could never be continued, so it sat asking for a decision nobody could take — for a week, in the roster this was built against. Such items now settle on boot as failed and deliberately not cancelled: a cancellation is journaled as a rejection and feeds the demotion streak, and losing a run file is the app's doing, not a verdict on the worker's judgement.

## [0.16.0] - 2026-08-23

### Added
- **Preview Office files without Office, on every platform.** `.doc`, `.docx`, `.xls`, `.xlsx`, `.ppt` and `.pptx` render inside Overcli with no Word, Excel or PowerPoint installed. Three converter backends are raced rather than queued — LibreOffice where it exists, Quick Look on macOS, Office COM on Windows — so a hung LibreOffice no longer costs you thirty seconds before the preview that would have answered instantly. The converted result renders into a `sandbox=""` frame with no scripts and no same-origin access, under a CSP that blocks every outbound channel, because a document someone emailed you is untrusted input.
- **Everyday projects.** Overcli without a repo, for people who have documents rather than code. Describe what you want and it scaffolds a folder in `~/Documents/Overcli Projects/`, prepares an undo history for it, and drops you straight into a conversation pointed at it — no file dialog, no path decision, and no mention of git anywhere in the flow. A folder you already have can be brought in the same way: the "New agent" screen used to dead-end on `Run \`git init\` in <path>` with nothing to click, and now offers a **Turn on history** button that does it for you. Three starter flows ship alongside it — review my documents, draft or update a policy, clean up a spreadsheet — because a new user needs something concrete on day one.
- **A documents view that looks like Drive, not like a file tree.** Everyday projects open into a card grid with real file-type icons, human names and "edited 2 days ago", one folder at a time with a breadcrumb. Code projects keep the explorer tree they already had — a nested column of monospace paths is the right tool for a repo and the wrong one for a folder of Word documents. Drag documents onto it from Finder to add them, and the project's own `.git` never shows up in the listing, because showing it would undo the entire point.
- **New documents you describe rather than name.** "A one-page summary of our Q3 results for the board" writes the document and opens it, running on the same one-shot transport as the flow and worker drafters — whichever CLI you are already signed in to. A **Blank** tab sits beside it for the times you already know what you want to write, with plain-word types (Document, Spreadsheet, Web page) instead of extensions. Filenames the model picks are rebuilt before they touch disk — basename only, extension from an allow-list — and a collision is numbered rather than overwriting the document that was already there.
- **Ask for a change to a document in one line.** At the foot of any open document: "make this shorter", "summarise the course material into this". It runs on the *fast* model rather than the strongest one, streams into the bar so you can watch it work, and then stops — the proposal is shown as a before/after diff with **Keep changes**, **Undo it** or **Try again**, and your document does not move until you choose. Highlight a passage first and only that passage is sent, with the rest of the file as context, which makes the model's worst habit — quietly dropping paragraphs it was not asked about — impossible outside your selection. **Stop** cancels a turn in flight and reclaims the process rather than leaving it running for nobody.
- **Documents save themselves, and every version is recoverable.** Everyday projects auto-save a few seconds after you stop typing, because nobody outside software thinks about saving. What makes that safe is the second half: Overcli now captures a version whenever something finishes — a rewrite kept, documents added, a spell of editing ending — and **Earlier versions** lists them in plain language with a **Restore** button. Restoring moves forward rather than rewinding, committing the current state first and the restored one on top, so putting the folder back is itself undoable. Large binaries are deliberately skipped: git can never reclaim a stored blob, and a big attachment revised twenty times would quietly cost a gigabyte inside someone's Documents folder.
- **A markdown split view.** Source on the left, rendered on the right, live as you type — for the person who can read a document but would rather not write `**bold**`. Offered only for files that are both editable and previewable, so it never appears next to a slide deck.
- **A folder you already have becomes an everyday project, and back again.** Any project can be switched between "everyday" and "code" from the sidebar, through a sheet that says exactly what changes — the documents grid instead of the file tree, plain-language history, auto-save — and nothing about the folder's own contents moves either way. Turning it back off leaves every file exactly where it is.
- **Workers file their documents into your folder, not only into the cabinet.** A worker hired for an everyday project can now deliver its output to the project folder itself, where its owner actually looks, instead of only to Overcli's own archive. Only documents travel — a run that also wrote a build script leaves the script behind — the folder must carry the everyday marker, each run is filed exactly once, and the arrival is checkpointed so it can be undone like anything else. Oversized files stay in the cabinet and say so in the log.

### Changed
- **The changes bar speaks about history, not saving.** With everyday projects auto-saving, "not saved yet" was telling people a file sitting in front of them on disk was unsaved. The badges now read *in history* / *new change* / *in history · edited*, leaving "saved" to mean the one thing it should.
- **The file explorer's empty state offers a way in.** It used to say "Pick a project or workspace from the sidebar" — an instruction where an action belongs. It now lists your recent projects as cards, with both ways to start a new one underneath.
- **Hidden drafting turns no longer boot your MCP servers.** Drafting a flow, hiring a worker or rewriting a document calls no tools at all, but each spawn was starting every configured MCP server before the first token. They now run with `--strict-mcp-config`, which is most of the wait on a machine with a few servers configured. Turns that genuinely need those servers — the orchestrator's producer above all — are untouched.

### Fixed
- **AI-drafted flows stay on models that actually exist.** A drafted flow could name a model the signed-in backend does not serve, and the run only failed at the step that used it. Drafts are now validated against the live model list and snapped back to the backend's own default tier.
- **Standing worker reports.** The worker report pane, its day axis and its per-worker journal shipped over several releases with no changelog entry; they are recorded here.

## [0.15.0] - 2026-08-22

### Added
- **A Timing tab that shows where a turn's time actually went.** The per-turn model-vs-tools breakdown shipped a release ago and was never announced.
- **Reasoning effort is set per backend.** A per-backend reasoning effort control, plus a fix that makes a change take effect on the live turn rather than only the next one.
- **Download a previewed file to your Downloads folder.** A one-click copy out of the preview pane, alongside the file's own path.
- **Real usage quotas, read from the CLIs rather than estimated.** Shipped alongside local-model flow reliability work and a pass over the workers/flows UI.
- **The desk shows the shift while it is being worked.** A worker mid-shift left its desk blank: one word in the strip above the composer ("Read", "Bash") and, under it, yesterday's transcript sitting perfectly still — so the moment you most wanted to watch was the moment the page had least to say, and the only place the planning turn streamed was the Shift tab, which is a different tab. The turn in flight now writes itself into the bottom of the desk as it happens, where the next thing always goes: a rule announcing the shift by number (the engine stamps it before the turn starts, so it is this shift's number and not the last one's), then the worker's own prose arriving a token at a time, with the tool it is in right now beside its name. An errand does the same without the rule, because its ask is already sitting above it as your message. A day whose only content is the turn in flight is no longer called an empty day — the first shift of the morning starts on a cleared desk, which is exactly when "nothing here" would be the most wrong thing the page could say. The desk follows the writing, with one rule: a turn STARTING always scrolls into view, because that is the answer to "did it hear me", but once it is running the desk only follows while you are still standing at the bottom. Scroll up to re-read yesterday's proposal and it stays where you put it rather than yanking you back down every time a token lands.
- **A shift you can actually read, search, and answer back to.** A planning turn is the longest single piece of prose this app produces — the worker says what it pulled, what it ruled out, and why — and the desk was rendering it in a chat bubble: 12px type, the full width of the window, a clamped box with its own scrollbar inside a transcript that scrolls underneath it. Past a few hundred words that is a document being shown in a message slot, and the sweep across seventy Jira tickets is several thousand. Any turn now opens in a reader — **Read in full ⤢** on the expanded shift, the errand, and the Shift tab's current card — at document size on a capped measure, because line length was most of the problem and a wider box that keeps 200-character lines fixes nothing. It has a find box (⌘F, ⏎ / ⇧⏎ to step, a running match count, wrapping at both ends), which is the thing you actually want when hunting `RED-6787` in a wall of prose; matches are painted through the browser's highlight registry rather than by wrapping them in tags, so the search cannot mangle the rendered markdown it is searching. There is deliberately no *replace*: a turn is the record of what a worker did, keyed to its own journal and to the runs behind it, and a find-and-replace over it would be a way to rewrite that record. What you get instead is a note. Notes are journal entries, not annotations, and that is the whole point of them — a worker reads its journal before planning every shift, so "the Panasonic ticket is blocked on their side, stop re-proposing it" reaches the worker the same way its own history does, without editing a job description that is about the job rather than about this piece of work. Notes show on the turn they were left against, in the Journal tab as the one line in there a person wrote, and they go with the shift if you delete it.
- **Every worker gets a line saying what it is.** A roster is a column of first names — Prometheus, Vantage, Bricklayer — and a name only means something to the person who typed it, on the day they typed it. The one place that said what a worker actually does was its job description, which is a page long and lives two clicks away, so telling six personas apart meant opening them one at a time. A worker now carries a tagline: one short line under the name, shown in the sidebar roster and again at the top of its desk ("Prometheus — the overcli innovator"). The hire drafter writes one from the job description as part of the contract, and it is an ordinary field in the editor, because the thing that names a persona is the person who employs it. Workers hired before this field existed are not left blank — the roster derives a stand-in from the opening of the job description, which is where a hired worker's "what it is" already sits, and clearing the field again returns you to that derivation rather than to nothing. What is happening still wins the line: a worker that is working a shift or waiting on your review says so, because a tagline is true all day and the status is only true now, and the roster's second line is the one place either can be read. Nothing in a shift prompt reads the tagline — it is a label for you, not context for the model.
- **A worker's run shows up in the sidebar while it's running.** Worker runs were kept out of the Chat sidebar entirely, on the rule that each machine-started run has one home — its worker's desk. That rule is right for the per-project Flows list, where a worker on an hourly clock would bury the runs you started yourself under a run per wake-up. It was wrong for the Active section at the top, which answers "what is going on right now": a worker run is the one thing on that list spending money with nobody watching, and hiding it made a crew of workers invisible while they worked. Worker runs now enter Active while they are genuinely happening — orchestrating, or stopped waiting for you — and leave the moment they stop, with no recency grace and no backfill, so the section never fills with finished machine work. They are named after their worker rather than their project ("Chief of Staff · worker"), since a run nobody started should say so before you click it, and clicking one selects that worker and opens the run at its desk: the row is a route to the run's one home, not a second copy of it. At most three worker rows at a time, newest first, so a roster waking up together cannot push your own work off the section — the Workers tab still has all of them.
- **Hiring and revising a worker take files, and keep running when you walk away.** Both AI boxes on the Workers tab were text-only, so "build the report the way this spec says" or "make it look like this screenshot" could only be described in prose to a model that could not see the thing being described — while the chat composer three tabs away had taken images, PDFs, CSVs and documents all along. The hire screen and the worker's ✨ edit box now take attachments through exactly the same intake the composer uses (pick, drop, or paste a screenshot straight into the edit box), and the files ride *both* turns: the one that writes the contract or routes the change, and the flow draft or flow edit it delegates to — a flow editor asked to match an example it was never handed is being asked to guess. They also get named in the prompt, since most CLIs receive an attachment as a path on disk with nothing saying whose it is or that it is meant to be read. Separately, and for the same screens: a hire is two full CLI turns and a revision is often two more, which is minutes of waiting in front of a page that unmounted the moment you switched tabs — taking the typed job description and the reply still on its way with it. That state now lives on the store instead of the component, so leaving is free. The turn keeps running, the elapsed counter keeps counting from when it actually started rather than restarting at zero on your return, the Workers tab shows a "still drafting" line that takes you back, and a finished hire opens in the editor whether or not anyone was watching. Revisions are per worker, because you can open anyone else's editor while one runs: Chief of Staff's editor no longer shows Prometheus's instruction and spinner, which read as the app having lost track of which worker you opened. A revision that lands while its editor is closed — which is what clicking any worker in the roster does — is held for that worker and applied the next time you open it, rather than being thrown away or landing on whoever happens to be open. The tab carries a line per worker being revised, and says when one is ready.
- **Ollama tells you when it's out of date, and when it's listening where it shouldn't.** The Local models page checked whether Ollama was installed and never whether the copy you had was one you should still be running — and it could only read a version at all while the server was up, so a stopped server was a blank. It now reads the version off the binary when nothing is listening, compares it against the latest stable release, and escalates from "there's an update" to a security finding once you are several minors behind, because Ollama ships security fixes in ordinary releases that never get a CVE number and a checked-in list of CVEs would go stale faster than the thing it protects. Alongside that it probes what is actually reachable: if the API answers on a non-loopback address, anyone on your network can run, pull and delete your models, since the API has no authentication. Nothing upgrades itself — an update opens `brew upgrade ollama` in a Terminal you can watch, or the download page. The server overcli starts is now pinned to loopback for both host and origins, which is also why a wildcard `OLLAMA_HOST` or `OLLAMA_ORIGINS` is only reported against a server overcli did not start: ours cannot inherit them, and a warning no button can clear is a warning people learn to ignore.
- **A worker is a file you can hand to another team.** A flow has always been portable — it lives on disk as YAML, so sharing one is sharing a file — and a worker was the opposite: JSON under a machine-local id, tangled up with the journal, the trust level and the project path that make it *this* install's worker. Two teams wanting the same worker meant one of them reading the other's settings screen and retyping it. A worker's Settings tab now carries the job as YAML, readable on the screen before you send it and saveable as a `.worker.yaml` file, with the flows it launches embedded whole rather than merely named — a worker whose flows are missing can propose nothing, so a file that only listed them would arrive broken. What deliberately does not travel is everything that is a record of what happened *here*: the id, the hire date, the shift history, the project path, and above all the trust level. An imported worker always lands on probation with every proposal parked for approval, because trust is earned against the person who will review the work, and a file that could arrive pre-trusted would be a way to hand somebody a worker that launches runs unattended on day one. For the same reason a shared worker can never ask to run in the working copy. Importing installs any flows your library is missing and never overwrites one it has, saying plainly which it added, which of yours it kept, and which are still missing and will therefore never launch; the worker itself opens in the hire editor for you to point at a project and hire yourself, so an arriving file is a hire you make rather than one that starts running.
- **Workers draw from one pot, paid down the roster in order.** Every worker carried its own monthly budget and nothing carried the sum, so the number that actually mattered — what the whole crew can spend this month — existed nowhere and had never been approved: eight workers at $10 was an $80/month exposure assembled one hire at a time. The roster's up/down arrows had the matching problem from the other end, moving names around without moving anything real, which is why arranging the list felt like tidying rather than deciding. One change fixes both, because they were the same gap. There is now a single monthly pot, and it is paid down the roster: a worker may spend only what is left after everyone above it is funded to its own cap. Dragging a worker up is a funding decision you can watch land. A worker's unspent cap is held for it rather than handed to the hungry worker below it, and that reserve evaporates as it spends — so the worker that runs your morning cannot be starved by the one that tidies changelogs, whatever order they happen to burn money in, while money the top of the roster does not claim still trickles to the bottom. Pausing a worker releases its reserve to everyone under it, which makes pause a budgeting tool and not only a scheduling one. Lowering the pot squeezes the bottom of the list first, never the top. None of this needed a second budget field: priority plus the caps that already existed is the whole rule. A new Funds screen shows the pot, what is spent, what is claimed, and where the waterline falls across the roster, with the reordering on the same screen as its consequence — dragged, because a queue you rearrange by nudging rows one place at a time is a queue you stop rearranging, and "this one matters most" is one gesture rather than five clicks. The arrows stay, revealed on hover or focus, since a drag-only list cannot be reordered without a mouse. An upgrading install starts with a pot equal to the sum of the caps it already had, so day one behaves exactly as before and the pot only begins to bite when you lower it. Shifts below the waterline skip quietly and journal why, and the pool running dry notifies once for the whole roster rather than once per starved worker.
- **A worker renders its report when you open it.** A worker hired to produce a page — a dashboard, a daily brief — is one you open in order to LOOK at something, and looking cost three clicks every morning: Files, then today's job folder, then the file, in a folder whose name is different every day. Selecting a worker now opens what it made in the preview beside its desk. Which output that is comes from a new setting under Settings → On arrival, and its options are read off what the worker has actually filed rather than typed in by hand or read out of its flows — a flow that renders a page declares the receipt and never names the page, so the flow definition is the one place that cannot answer this. The default needs no setup at all: the newest renderable file the worker has, which for a daily report is today's. Pin a specific filename and it follows that output across job folders, showing yesterday's copy when today's run has not landed yet rather than silently substituting something else; a worker that has only ever written prose offers nothing to pick and opens nothing. Markdown is deliberately not renderable here — every job files several .md artifacts, so treating those as reports would mean picking one arbitrarily and putting it in front of you on every click.

### Changed
- **The debug sheet reads flow and worker runs, not whatever chat you had open.** Timing answered a question nobody was asking there: Flows and Workers pick a run through their own store and never touch `selectedConversationId`, so opening the sheet over a running flow showed the numbers for some chat from an hour ago — confidently, with no sign it was looking somewhere else. Both tabs now follow the active run. A run has no single transcript to follow, since each participant keeps one conversation across every step it runs, so the sheet lists the participants that have opened one and defaults to the one the run is actually at — the running step's, the step a paused run would resume into, or whoever ran last. The participant a run is focused on was already being derived inline for the subagent drawer; both now ask the same function. Two things to know reading the result: a participant's rows cover every step it ran rather than one row per step, and a step with a rebound critic blends the critic's turns into it, because critic traffic shares the participant's stream. Worker shift and errand turns still show nothing at all — those run through a hidden one-shot conversation whose events never reach the renderer.
- **The turn-timing bar names which tool ate the time.** The breakdown split a turn into model and tools, and "tools" was one grey block — which is enough to know the model wasn't the problem and not enough to do anything about it, since a turn that spends forty seconds in tools spends it very differently depending on whether that was one `Bash` build or thirty `Read` calls. The tool share of each bar is now split by tool name, with a legend under each turn giving each tool's busy time, its call count, its slowest single call and any errors, plus the same split across the whole conversation in the header. Color is spent on cost rather than on identity: tools are ranked slowest to fastest and laid on a red → amber → green ramp, so the expensive one is findable without reading a number, and nothing lands near the blue accent the model's share is drawn in — a blue tool slice beside a blue model slice hides the one split the bar exists to show. The ranking is computed once from the conversation totals, so a tool keeps its color across every turn. MCP tools are shown as `server:tool` instead of their full `mcp__…` name. Slice widths are the merged wall clock divided in proportion to each tool's busy time, because parallel calls overlap — four greps at once cost one grep of wall clock — so the slices add up to the tool total exactly while the legend reports what each tool actually spent. The copied TSV gains a `top_tool` column.
- **A worker's report opens at half the window, not a quarter of it.** The side preview pane opens at a fixed 640px, which is right for a file peeked at beside a chat and wrong for the thing you came to look at: selecting a worker renders its report automatically, and on a wide screen 640px is a quarter of the window, so every arrival began with the same drag. On the Workers tab the pane now opens splitting the content width evenly with the desk. Dragging it still wins — once you size it yourself, that width holds for the rest of the session and no later report undoes it.
- **The local model catalog is current again.** Ollama publishes no API for listing its library, so the catalog of suggested models is hand-maintained — and it had rotted by about sixteen months: outside the Gemma 4 entries nothing was newer than Llama 4 Scout, Qwen stopped at 2.5, and a third of the list was 2023–2024 vintage (Mixtral, Code Llama, CodeGemma, StarCoder2, granite-code, Codestral). Because "recommended for this machine" ranks by the hand-typed release month, a fresh install on a 64GB Mac was being pointed at a two-year-old model. Refreshed against ollama.com/library: 27 tags added, 18 obsolete ones dropped, 46 total. Every tag was confirmed to resolve in the registry, and sizes and licences were read off the registry's tag pages rather than recalled — which caught two errors in the entries that were already there, Gemma 4 having moved to Apache 2.0 (it was listed under the Gemma licence, which now applies only to Gemma 3 and earlier) and Llama 4 Scout being 67GB rather than 65GB. Also worth saying plainly: `modelSupportsTools()` answers from this same list, so a model missing from it silently gets no tools — which is why the new entries carry the tool flag the registry reports rather than a guess. Models that publish cloud-only tags (DeepSeek V4, GLM 5.x, Kimi K3, MiniMax M3, Mistral Large 3) are deliberately absent, since this pane is about what runs on your own machine.
- **The roster shows a worker's latest shift, not every shift it has worked today.** A worker on an hourly clock filed a row per wake-up, and most of those rows say the same thing — the Slack fielder that swept the channel five times and found nothing to answer spent four lines saying "nothing launched", which pushed the four workers below it off the bottom of the list. Repetition is the point of a clock and not something the sidebar has to reproduce. A worker now shows its newest shift, because "when did this one last wake up" is a question the roster has to answer even when the answer is "and it found nothing", plus any earlier shift still holding candidates you have not reviewed or work still running — an empty shift at 3pm must not hide the one at noon that proposed three things and is waiting on you. Errands are untouched: each one is a distinct thing you asked for, so they all keep a row, and they now have a budget of their own rather than sharing one with the clock that could spend it all before your errand got a line. Both groups say how many rows were folded away, since a group that quietly drops eleven shifts reads as a worker that only ran one, and the full day is a click away on the desk.
- **Dragging a pane divider stays smooth beside the Workers tab.** The handle wrote its width through React state on every pointermove, so the frame rate of a resize was the render cost of whatever the owner drew — fine beside a memoised chat, choppy beside a roster and a transcript full of rendered markdown re-rendering forty times a second for a number only one `style.width` consumes. A drag now writes the width straight onto the panel and reports it once, on release.

### Fixed
- **A step that forgets its `<output>` wrapper is asked for it instead of stalling the run.** AI-drafted flows routinely produce read-only steps whose prompt says "investigate, do not write anything" — and a model reading that alongside "wrap your deliverable in `<output name="spike.md">`" treats the block as a write it was just forbidden to make, so it ends the turn with prose and the run pauses on "produced no `<output name="spike.md">` block", several minutes of correct investigation sitting in the transcript unusable. Two changes: the output contract now states that the block is text in the reply rather than a file, so it never conflicts with a read-only constraint and a read-only step still emits its findings; and when a step does finish without one, the runtime asks its participant once — in the same conversation, where the work is still in context — to re-emit the deliverable, reading it back off disk if that is where it went. Only a second miss fails the step, and every fresh attempt gets its own ask. The flow drafter is also told to phrase a step's constraints around what it may change, never as "produce nothing".
- **Clicking "Work now" no longer locks every worker's editor.** `workers:workShiftNow` doesn't resolve when the shift STARTS — it resolves when the whole planning turn has run, which is minutes. The renderer held one app-wide `busy` flag across that call, and the contract editor's Save button reads the same flag, so starting a shift by hand on one worker greyed out Save on every worker's editor and left it reading "Saving…" on a form nobody had touched. The flag now means only what the editor needs it to mean — a save or an import, both of which take a moment — while "this worker is working" is tracked per worker, where it always belonged: the shift's own progress already says so from the instant the engine announces it, and a new per-worker flag covers the gap between the click and that announcement so the button still can't be pressed twice.
- **A worker's Settings tab opens at the top, where the Edit button is.** The desk transcript and the other five tabs share one scroll box, and the effect that parks a conversation at its newest message ran on every tab change — so Settings opened somewhere in the middle of the contract with its Edit button already scrolled off, and Journal and Stats opened at their oldest, least interesting end. Only the desk is a conversation; the rest are documents, and a document opens at the top. The transcript still parks at the bottom on arrival and as turns land, and a shift landing while you read the settings form no longer yanks the form back to the top.
- **Re-running Verify after fixing its findings now reviews the fix.** Once a verifier exhausted its automatic retries, you could hijack that premium participant, tell it to repair the files, watch it make the changes, and then re-run Verify — only for the re-run to receive the old diff captured at the last ordinary step boundary and reject the same code again. Diff inputs are now regenerated from the live worktree immediately before a consuming step runs, so edits made during the paused side-chat are part of the verification. Large diffs also use content-addressed attachment paths, making a refreshed snapshot distinct from the earlier file already present in the resumed model's conversation.
- **Nightly updates use semver-compatible release tags and feeds.**
- **Backend health recognizes the current Copilot credential path and parsed Claude login status, gives probes ten seconds, and retains known-good status through timeouts.**
- **Worker hiring reports authentication failures and bounded parse diagnostics.**
- **"Opened Terminal" now means a Terminal opened.** Update Ollama reported that it had opened a window running `brew upgrade ollama` and, for anyone whose Mac had not granted overcli Automation access, opened nothing at all — the message was hardcoded next to a launch whose result was thrown away. Three layers were hiding the same failure: the AppleScript went out through a detached `osascript` with its output discarded, so macOS refusing the Apple Event (-1743) looked identical to success; the launcher returned `ok` for a spawn that had merely *started*; and the caller ignored even that. It also used a bare `do script`, unlike the workspace launcher beside it, so there was no window to notice the absence of. The launcher now waits for `osascript`, reads its exit status, and opens the window with `open -a Terminal` first — that half needs no Apple Events, so a blocked install still gets a window to paste into — and a refusal comes back as where to grant the permission plus the exact command, carried as its own field rather than buried in the sentence so the Local models page, the sign-in banner and the CLI setup guide can all offer it as a mono line with a Copy button. Failures land in diagnostics too. The packaged app could never have been granted that permission in the first place: the hardened runtime denies Apple Events outright without `com.apple.security.automation.apple-events`, and macOS will not even show the prompt without a usage description, both of which are now shipped. Separately, `brew upgrade ollama` was offered to anyone who merely *had* Homebrew; it is now offered only when Homebrew is what installed Ollama, since for a .dmg install that command has always been an error message in a window rather than an update.
- **Picking a worker in ⌘K opens the worker.** Every other row in the palette goes where its subtitle says it goes; a worker row opened the hire editor instead — a form for changing the contract, in answer to "show me this worker" — and it did not even select the worker on the way, so cancelling the form landed you on whoever the roster had highlighted before. Worse, the editor renders over a worker's run, and a run outranked it: pick a worker while its errand was on screen and the palette closed with the screen unchanged, which reads as the palette being broken rather than as a screen losing a fight it should never have been in. ↵ on a worker row now arrives at its desk, the same arrival as clicking the row in the roster — today's page, its report beside it, no run or half-written draft left covering it — and ⌘↵ opens the editor for the times you did mean the contract, matching what ↵/⌘↵ already mean on a flow. An open draft now also wins over a worker's run wherever it comes from, so the roster's own Edit button no longer silently does nothing mid-errand.
- **A link in a rendered page opens in your browser.** A preview frame sits on an opaque origin with no top-navigation, the app's own `frame-src` refuses a same-frame hop to https:, and main's bounce-to-the-browser handlers never see a subframe navigate — three independent refusals, so clicking a link in an .html report or a React component did nothing at all, with no error to explain it. Links now leave through the one route out: the frame is allowed popups, an external link becomes a `window.open`, and Electron's window-open handler denies the popup and hands the URL to the OS through the same allowlist every other link in the app goes through. The frame gains nothing it can act on itself.
- **A paused step says why it failed.** A `failure` pause is not necessarily a reviewer that said no — a step that emitted no `<output>` block, crashed, or tripped the silence watchdog lands in exactly the same state, and the banner told all of them "a reviewer that didn't approve", sending you hunting for a rejection nobody had written. The runtime already records the real reason on the attempt, so the banner now shows it, falling back to the old wording only when there is nothing better than a guess.
- **A run opened from a worker gets the run's files, not the conversation's.** The file editor recognised a flow run only in the Flows tab, so the same run pane shown on a worker's desk resolved its paths — and ran its diffs — against whichever conversation happened to be selected underneath, in that project's repo. Both places now scope the editor to the run, and a worker's desk keeps its own set of open tabs the way a conversation does, so arriving at a worker no longer leaves the last worker's page open under the new worker's name.
- **A file a worker wrote is filed with the work, not left in a folder that gets deleted.** A run's deliverables were taken to be its step artifacts, so anything a step WROTE rather than recorded was never filed anywhere. That is not an edge case: Overcli's own flows tell steps to render a dashboard or a chart "alongside the run artifacts" and hand back a receipt, so the receipt was filed and the thing it described was not — the Files tab listed `dashboard_receipt.md` describing a page you could not open from it. The page itself sat in the run's working root, which for a workspace run is a coordinator directory that is deleted with the run, so the report the worker was hired to produce was on a timer nobody could see. A finished run now also files the loose files it left at that root, copied byte for byte so a PNG or a PDF survives the trip intact. The sweep only ever looks at a root Overcli itself made — a folder of symlinks plus the three context files, where every regular file is by definition something the run put there — so no project source can be swept up as output, and only files touched after the run started are taken, which keeps a long-lived workspace root from re-filing last week's leftovers under today's shift. Runs still on disk get their files on the next fold, so today's report is filed retroactively rather than only the next one.
- **An HTML file previews the way it does in a browser.** The preview frame ran with an empty sandbox, and a document handed to a frame as `srcDoc` inherits the app's own `script-src 'self'` besides — two independent refusals of the same thing. So every page that builds its own DOM painted a blank white rectangle, including the CDN React + Babel + Tailwind page Overcli's dashboard flows instruct agents to write: the app declined to display the file it had just asked for, and the only way to read your own report was to find it on disk and open Chrome. HTML previews now take the route compiled components already took — main serves the document over `overcli-preview://` under a policy that permits the remote script and in-page compilation those pages are built from, and the frame runs with scripts enabled but no same-origin, so the page can run and still cannot reach the app around it. Local stylesheets and images are inlined as before, since a `file://` sibling is unreachable from a preview under any policy.
- **A flow step can read the inputs it was handed.** An input over 20 KB is not pasted into the step prompt — it is written under the app's own data directory and the prompt references the path, so a 200 KB draft costs the step one Read instead of most of its context. But the step's session was launched knowing only its working directory, and the CLI settles that scope when it starts rather than through the permission prompt, so the path it was given was one it could neither open nor ask about: the step was handed files it was structurally unable to read, and the failure arrived looking like inputs that had gone missing. It bit hardest at the end of a long flow, where the artifacts are largest and the step assembling them declares the most inputs — a report step given a draft and its fact-check found both unreadable, and the careful ones reported the blocker rather than rebuilding the deliverable from memory, which is the better failure and still a failure. The run's attachment directory now travels with every send the run makes. It is created when the run starts rather than when something is first attached, because the allowed set is read once as a session opens: a directory that came into existence three steps later would be granted to nobody.
- **An HTML preview can no longer phone home or read files it wasn't shown.** The `document` preview policy allowed `connect-src https:` alongside the remote script it needs to run, so a page dropped into a report could `fetch`/`XHR`/`sendBeacon` anything it liked; a compiled `bundle` preview keeps that permission, since it never runs script it didn't write itself. Separately, an inlined `<img src>` or CSS `url()`/`@import` was read and base64'd (or spliced in as text) regardless of extension, so a reference like `../.env` was silently readable from inside the preview — including through a stylesheet's own imports, which bypassed the direct-reference check entirely. Both routes into a file now stop at the same allowlist of previewable image, font and stylesheet types. Rendering an agent-written dashboard that calls a live API will now show no data instead of fetching it, which is the trade for a preview that can't exfiltrate whatever it can see.

## [0.14.2] - 2026-08-14

### Fixed
- **A workspace run no longer dies on a base branch one member never had.** A schedule stores whatever branch its editor was showing when it was last saved, and that name outlives the target it was picked against: point the schedule at a workspace afterwards and every member repo gets forked off a branch that only ever existed somewhere else. The first repo without it failed the entire launch — one stale string taking out all twenty-three members in under a second, every weekday morning. Retry could not help, because the base branch lives on the batch record and each attempt replayed the same value, and neither could the editor, which hides the branch picker for workspace targets and so rendered the offending name invisible and unclearable in the one place you would go to fix it. A shared base is a hint across N independent repos rather than a contract — the launcher only ever offers names present in every member, but nothing keeps a stored one honest — so a member that does not have it now forks off its own default and says so in the log, instead of taking the run down with it. Single-project runs stay strict: there the branch was chosen against that one repo, so a missing one is a real error and not a mismatch to paper over. The editor also stops holding a base branch it does not show, clearing it when the target changes and dropping it for workspace targets and non-worktree runs, so the value cannot go stale out of sight again ([#140](https://github.com/overcodelions/overcli/pull/140)).

## [0.14.1] - 2026-08-13

### Added
- **A scheduled orchestration can launch a capped number of its own proposals.** Scheduled batches always parked: the producer investigated overnight and every candidate sat waiting for a click. That is still the default, but for a schedule whose producer you have learned to trust it means the useful half of the work waits on you. `autoApprove` opts out of the waiting and not out of the bound — the hazard was never "a scheduled batch launched", it was "the producer decided at 3am that there were thirty things to do", so the cap is required rather than optional and `maxConcurrent` does not do this job (it limits how many run at once, not how much work is committed to). The first N candidates queue in producer order, which is best-first by construction; everything past the cap stays proposed with a note saying why, so an unexpectedly large morning degrades into an ordinary parked batch instead of a dozen unsupervised worktrees. The cap is clamped in the engine as well as validated at save time, so a schedule written by an older build or hand-edited on disk cannot talk it into an unbounded dispatch ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **The Orchestrator has an idle stage.** Three numbered panes were sized for the ten minutes you spend composing a batch and wrong for the hours afterwards: Ask and Map sat empty while the ledger — the only thing with anything in it — was squeezed into a third of the width. The tab now has two modes. Composing keeps ①②③ and the split screen; idle shrinks Ask to a one-line launcher, drops Map, and gives the runs the full stage with a header of their own. The step numbers go with it, because nothing is mid-sequence there. Every count in the new runs bar is a filter, since a number you cannot act on is a run row given up for decoration, and clearing the finished two thirds of a busy ledger is the biggest thing that bar can do for the runs you actually came to watch. A batch awaiting approval renders whole regardless of the filter — an obligation is not a list entry — and a half-launched batch says how many already went, so "Discard the rest" declines the parked items instead of aborting live worktrees ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **A retried flow step is told why it was sent back.** `on_fail.goto` re-ran its target with only the inputs that step was authored with — a build step declaring `plan.md` got `plan.md` again and never saw the `review.md` that had just rejected it. So it produced the same work, got rejected again, and burned the entire retry budget doing it. The retry now leads with what happened: who rejected it, the verdict in one line, which attempt this is, and the rejecting step's artifact fed in even though no flow author could have declared an input that does not exist yet. The same notice shows in the step header, so the loop is visible in the run pane rather than looking like a step that inexplicably ran twice ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **The schedule editor is rebuilt on the flow editor's skeleton, with a fourth starter.** Same header, two-column body, card sections and save-at-the-top: these are the two places in the app where you build a thing rather than run one, and they were shaped differently for no reason a user could see. Save moving up matters on its own — on a tall schedule you had to scroll past everything you had just decided in order to commit it. The new starter answers Slack questions hourly through the working day, and it is the first one that repeats on an interval and the first that makes no worktree: it reads code to answer and writes to Slack, so forking the repo nine times a day would leave a trail of empty branches. Its prompt tells it to leave anything it cannot answer confidently alone, because an unattended run that guesses in public is worse than one that does nothing ([#139](https://github.com/overcodelions/overcli/pull/139)).

### Fixed
- **Effort levels reach the Claude CLI instead of killing the turn.** The flag was sent as `--thinking-effort`, which has never been a real option, so every send with a non-default effort level died on the spot with `error: unknown option`. The real flag is `--effort`, and older CLIs reject that one just as hard — hence the probe: the flag is dropped unless the installed binary advertises it, cached per binary path ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **A long producer turn is budgeted on silence, not a wall clock.** A producer that searches two issue trackers and diffs three repos does dozens of MCP round-trips, and the flat five-minute ceiling killed healthy runs mid-investigation — a schedule spanning several sources failed every single morning with "Timed out after 300s." A wall clock cannot tell "wedged" from "busy": raise it and a hung turn sits there, lower it and honest work dies. The budget now keys off idleness, resetting on every streamed event including tool-only batches, which is what a long investigation actually consists of, with a far-off absolute ceiling still behind it ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **A scheduled workspace run gets its worktrees.** A workspace root is not itself a git repo, but a run targeting one mints a worktree per member. The scheduler asked git about the root and nothing else, so every scheduled workspace run silently downgraded from `worktree` to `cwd` — unattended edits landing straight in the checked-out tree, which is the exact thing choosing a worktree is meant to prevent. The editor made the same mistake in the other direction, greying out "Fresh worktree" for a workspace and quietly pinning it to the working tree ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **Flow run rows have a fill again.** `bg-card/40` is an opacity modifier on a CSS-variable colour, which compiles to nothing — so every row in Active and Recent rendered as a bare outline with no background at all, which is why they read as all border and no substance. Named blends replace them, with no border, and a live run gets a faint accent wash rather than a coloured edge ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **The flow library is ordered by the name you see.** Flows arrived sorted by id, which is the filename on disk and is renamed independently of the flow's name — so the list looked alphabetical right up until someone renamed a flow without renaming its file. Every surface that takes this order as given (the schedule editor's picker, the Orchestrator's per-candidate select, the library's own groups) now gets it sorted by the string it renders ([#139](https://github.com/overcodelions/overcli/pull/139)).

### Changed
- **The Gemini catalog moves to the 3.x line.** 2.5 Pro and 2.5 Flash were the entire list and both are a generation behind. Flash iterates faster than Pro — 3.7 Flash is out while 3.1 Pro is still the newest Pro id — so Pro stays first and remains the auto-pick and drafter default, with Flash and Flash-Lite behind it. The split gives the backend a real middle tier for the first time, so a drafted flow asking for a cheaper critic step finally gets one instead of degrading upward onto the strongest model available. - **The file explorer keeps up with the agents writing into it.** The tree listed its root once per mount, so a file an agent dropped into the project simply wasn't there until you closed the pane and reopened it — the one view whose whole job is telling you what exists was the last to know. A recursive watcher per root lets the renderer relist itself as the tree changes underneath. The walk behind it is now two functions rather than one: a sync form for callers already on a blocking path, and an async one for the tree, which relists on every agent write and would otherwise stall the main process to do it ([#136](https://github.com/overcodelions/overcli/pull/136)).
- **Worktrees that outlived their work have an exit ramp.** Worktrees are deliberately long-lived — a conversation keeps its tree so you can reopen the chat and carry on — but nothing ever removed one when the work was genuinely finished, and two paths orphaned them outright: `pruneOldRuns` evicts a run's metadata without touching the worktrees that run recorded, and a failed removal left the tree on disk with nothing pointing at it. A sweep now finds the trees nothing references any more and offers them up. It surfaces as two Settings panes rather than one, and the split is the point: **Storage** reclaims disk and is scoped to orphans, while **Conversations** deletes history. They look similar enough to merge — both are cleanup, both key off worktrees — but the trade runs opposite. The conversations are typically kilobytes each, so folding them into a disk pane would have meant offering to destroy hundreds of chats in exchange for no measurable space ([#136](https://github.com/overcodelions/overcli/pull/136)).

### Fixed
- **A flow step's rebound critic gets the number of rounds you asked for.** `max_iters` is a step's round budget for its critic, but the runtime never handed it over — it passed the critic's backend, mode, model and persona and stopped there, so the budget fell back to the interactive default of three. ## [0.13.2] - 2026-08-03

### Fixed
- **Conversations you're done with stop holding a CLI open.** `claude -p --input-format stream-json` stays resident for as long as its stdin is open, and it brings every configured MCP server with it, so a session costs its full footprint from the first message until the app quits. Nothing reclaimed that: archiving or deleting a conversation dropped the row and left the process behind, and a finished turn reports `isRunning: false`, so it was invisible to the running indicator and to every "stop it first" path in the UI. A measured session is about 1 GB across roughly fifteen processes — the CLI itself is under half of it, and the rest is the MCP servers it started, which sit two levels down (`claude` → `npm exec @modelcontextprotocol/server-x` → the server proper). Thirty of those parked is tens of gigabytes, and one machine was carrying a session whose conversation had already been deleted. Archive and delete now release the runtime, and a sweep retires any session idle past a timeout (Settings → Advanced → *Release idle sessions after*, 30 minutes by default, or Never). The sessionId is persisted, so the next message respawns and `--resume`s the same thread — the only cost is a slower first turn. The sweep declines in every case where teardown wouldn't be free: a turn still in flight, a permission prompt waiting on you, or a session with no sessionId to resume from, where reaping would be history loss wearing memory savings as a disguise. Archiving keeps its promise to be safe mid-turn and skips a busy session rather than cutting it short.

## [0.13.0] - 2026-08-01

### Added
- **Scheduled runs.** A schedule is a trigger on work you already defined, not a new kind of run, so it lives as a segment inside Flows (Library | Schedules) rather than a fourth top-level tab that would have become a third place to launch from. The firing arithmetic is pure and testable: a schedule missed while the app was closed either coalesces into one catch-up run or is skipped, one that comes due mid-run can skip, queue a single follow-up or replace what's going, and editing a cadence re-anchors rather than firing on save. The engine holds one timer per schedule, re-derived from the nearest due time and capped at 60s, so a sleeping laptop or a stepped clock self-corrects instead of drifting. A worktree target against a directory that isn't a git repo degrades to the folder rather than failing preflight — plenty of scheduled work pulls data or talks to other systems and has no repo to fork — and where a repo does exist the isolation still applies. Every firing notifies natively, because unattended runs need a way out ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Scheduled proposals the orchestrator parks for approval.** The second target shape, and the asymmetry with the first is the design: *run a flow* launches one run with a fixed prompt, bounded and reviewable, while *propose a batch* runs the orchestrator's producer against your sources and **parks** what it finds. Every item lands `proposed` and nothing launches until you approve it. Dispatching a batch unattended is the one thing a schedule must not do — the producer decides how many items exist, so a bad morning would fork a dozen worktrees with nobody watching — and scheduling the investigation is the valuable half anyway. Parked batches surface inline on the schedule's own row, listing the asks rather than counting them, since "5 proposed" says a decision is waiting without saying whether it's a good one. Inline actions are Review & pick, Launch all and Discard; per-item approval deliberately stays in Orchestrator rather than growing a second copy that would drift ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Interval triggers take days and an active window.** "Every hour, weekdays, 8am–5pm" is the normal shape for a repeating check, not an exotic one — without a window you'd accept 24 runs a day to get the 9 you wanted, plus weekends. The arithmetic steps first and then checks, so a candidate outside the window jumps to the next opening instead of walking through the closed hours one interval at a time; that also re-phases each day to the window's start, so an 8–5 hourly schedule armed at 8:37 runs on the half hour today and from 8:00 sharp tomorrow. Both ends are inclusive, a start after the end wraps midnight, and the day set then applies to the side the window opened on. Validation rejects an interval longer than its own window, which would otherwise be a silent alias for "daily at 9"; an unparseable window degrades to no window rather than to one that never opens ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Scheduled activity in the title bar.** Scheduled work is now visible from whatever tab you're on, and one click from being opened. Three states in priority order: violet for a parked batch waiting on your approval, pulsing sky for a run going right now, green plus a countdown ("Scheduled · in 3h") for armed and idle. Waiting outranks running deliberately — one needs a human, the other just needs time — and shape carries the distinction as well as hue, filled for something happening, still for ready. The countdown is what proves an idle schedule is alive rather than forgotten, so the bar ticks every 30s, and only while something is armed. It renders nothing at all when no schedule is enabled: a permanently-lit item in the one strip that's always on screen is noise for people who don't use the feature and blunts the signal for people who do ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Scheduled runs are numbered so occurrences are tellable apart.** A run's title falls back to the first line of its prompt, and a scheduled prompt is fixed by definition, so every morning's run was titled identically and the library became a wall of the same sentence. Runs and parked batches now carry an `[SR-n]` prefix. *n* counts firings of that schedule rather than runs globally — two schedules will both have an SR-1, which is the trade, because "the 12th morning triage" is a fact about the schedule where a global counter would just be a serial number. Manual fires take a number too: they don't advance the cadence, but they do produce a real run in the same list ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **"What's new" after an update.** Updates installed silently on quit, so the app could change under you overnight with nothing to say what landed. Release notes now open once on the first launch after an update — not when the update downloads, since installation is deferred to quit and at that moment you're still running the old build. The notes come from this changelog, bundled into the app, rather than the GitHub release body, which is generated from PR titles. Someone who skips two versions gets both, newest first, capped at four with the remainder counted rather than silently dropped. A fresh install is stamped as current and shown nothing — nothing is "new" on your first launch — and the nightly channel is excluded, where a panel every launch would only teach you to dismiss it. Reachable any time from About, which now also reports the real running version instead of a hardcoded `0.1.0` ([#129](https://github.com/overcodelions/overcli/pull/129)).

### Changed
- **The Flows header segments are a real segmented control.** They were two bare words with a background on the active one, so the inactive half read as a subtitle to the heading next to it rather than as something clickable. There's a track now — a recessed surface so both halves read as options, with the selection a raised pill — and inactive text moves from faint to muted, since faint is the tone this codebase reserves for disabled and metadata. Schedules also announces itself once: a slow 2.4s breathe and a "new" pip that retire permanently after the first visit, because a highlight that never stops is one the eye learns to skip ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **The sidebar's Active section is ordered by what you last touched.** Liveness earned a slot *and* set the order, so every step a backend advanced re-sorted the list under your cursor, and over the cap a busy run could evict the chat you had just typed in. Membership and order are separate now: liveness still earns the slot, but rows sit where you left them ([#128](https://github.com/overcodelions/overcli/pull/128)).

### Fixed
- **A worktree run's changes list no longer counts upstream commits as its own work.** Diffs started from the fork point captured when the worktree was minted, which is exact on the day of the run and wrong forever after — once the branch takes upstream in via a pull, merge or rebase, every one of those commits reads as part of this branch's work. One run whose PR had already landed showed 199 changed files, all of them other people's merges. The base is resolved live now, from `merge-base(base, HEAD)`, preferring remote-tracking refs over a local branch nobody has fetched in a week. Merging upstream *into* the branch doesn't push that point past the branch's own commits, so in-flight work survives; once the work lands, the diff correctly collapses to nothing. The old frozen baseline stays as both last resort and floor, which is what keeps a worktree forked from another feature branch from dragging its parent's work into the diff ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Reopening a compacted conversation no longer shows the summary as something you typed.** Replay dropped the compaction boundary entirely and rendered the summary the CLI writes as an ordinary user message — 25k characters you appeared to have sent. Replay now emits the boundary notice and drops the summary, matching the live stream ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Go to definition works in worktree runs and symlinked workspaces.** The renderer sent the conversation's root, which in those cases is not the tree the open file lives in, so the search found nothing. Resolution and validation now run against the file's own tree ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **"Run now" no longer resets the cadence or double-launches.** A manual fire stamped `lastFiredAt` like a real occurrence, which for an interval trigger restarts the whole clock — checking an hourly schedule at 8:59 silently cost you the 9am run you were checking on. A test drive is not an occurrence, so it leaves the cadence exactly as it found it. Separately, nothing guarded the window between starting a run and the launch resolving: `activeRunId` isn't set until it returns, and a worktree checkout leaves seconds in which the schedule looks idle, so a double-click on Run now — or a tick landing mid-launch — started a second run. An explicit in-flight set covers it, and ticks skip those schedules outright ([#128](https://github.com/overcodelions/overcli/pull/128)).

- **The UI no longer locks up while several agents stream.** Two causes, both on hot paths. Separately, a step whose backend died quietly had no path out of `running` at all. Steps silent for over 30 minutes now fail into the same recoverable pause a rejected step gets ([#122](https://github.com/overcodelions/overcli/pull/122)).
- **Flow steps no longer fail off a superseded process's close.** When a conversation's process is killed to apply changed launch params, it drains asynchronously while a replacement turn is already live; the dead process's late `running:false` was mistaken for the new step finishing ("produced no `<output>`") ([#115](https://github.com/overcodelions/overcli/pull/115)).
- **The app returns to what you were looking at after sleep.** Only the selected conversation was persisted, so a renderer re-init — macOS discards the render process during a long sleep — dropped you off any flow run, orchestrator batch or project welcome screen back to the default view. The full view identity is now persisted and restored ([#116](https://github.com/overcodelions/overcli/pull/116)).
- **The orchestrator's main-tree choice survives a reload.** The `runIn` toggle lived only in the renderer store, whose fresh default is `worktree`, so after a reload a batch you'd set to main tree silently went back to worktrees. The sticky batch-launch defaults are now persisted alongside the view ([#117](https://github.com/overcodelions/overcli/pull/117)).
- **Two new flows no longer overwrite each other.** A flow's id becomes its filename, and every blank flow started as the constant `new-flow`, so the second silently replaced the first. New flows get a collision-free id; editing an existing flow keeps its id ([#118](https://github.com/overcodelions/overcli/pull/118)).
- **An unknown step role fails validation instead of running "undefined".** A role that is neither a preset nor `custom` resolved to the literal system prompt `"undefined"` — a silent runtime failure ([#118](https://github.com/overcodelions/overcli/pull/118)).
- **Codex tool output that arrives as content blocks no longer breaks history.** Codex now writes `function_call_output.output` as an array of content blocks; the field is typed `string`, so an array poisoned every consumer that trusted the type and broke `runner:loadHistory` in the dedupe path ([#122](https://github.com/overcodelions/overcli/pull/122)).
- **Queued workspace context notices stay bounded.** Workspace edits queue a notice onto every conversation, cleared only when that conversation next sends — so one you never send to again accumulated them forever. One real workspace had 103 stacked notices (52 KB) on a single conversation, which would have prepended ~13k tokens of stale churn to its next message. Notices are now deduped and capped, on both load and save ([#122](https://github.com/overcodelions/overcli/pull/122)).
- **An explicitly chosen model is always passed to the backend.** Copilot conversations had no model field, and `--model` was omitted when the resolved model came back blank, so the CLI substituted its own default while the header still showed the user's pick. Resuming a session from the terminal also dropped its model ([#113](https://github.com/overcodelions/overcli/pull/113)).

### Security
- **AWS MCP entry migrated to the managed endpoint.** AWS put `awslabs.aws-api-mcp-server` into end-of-development. The catalog now installs the managed endpoint through a pinned `mcp-proxy-for-aws`, with the default region carried in `--metadata` rather than `env` (the managed server reads its region from proxy metadata, so the old env var silently stopped meaning what it meant). Existing installs are detected, badged **Legacy**, and can be reinstalled in place ([#122](https://github.com/overcodelions/overcli/pull/122)).
- **Credential leak in the auto-updater.** `electron-updater` pulled a `builder-util-runtime` that leaks `PRIVATE-TOKEN` and mixed-case `Authorization` headers across a cross-origin redirect — a production dependency doing authenticated network I/O on every update check ([#123](https://github.com/overcodelions/overcli/pull/123)).
- **Shipping-tree advisories cleared.** `fast-uri` (host confusion via failed IDN canonicalization, reached through the Agent SDK's MCP dependency), `body-parser` and `dompurify` are pinned to patched versions; build-only advisories in `axios`, `brace-expansion`, `electron-builder` and `postcss` are cleared too. The production tree goes from 1 high + 3 moderate to 0 high + 3 moderate — the remainder being a single Windows-only `@hono/node-server` path-traversal issue whose patch is a major outside the MCP SDK's declared range, and whose code path overcli never mounts ([#123](https://github.com/overcodelions/overcli/pull/123)).

- **Copilot as a reviewer backend is not supported.** Copilot's CLI takes prompts in argv, but the reviewer plumbing feeds prompts via stdin. Copilot is hidden from the reviewer picker.
- **Collab-mode rebound is disabled when Copilot is the primary.** Copilot exits after each turn, so the runner can't push reviewer pingbacks into it. Greyed out in the popover with an explanation. Tracked in [#19](https://github.com/overcodelions/overcli/issues/19).
- **Permission modes default / acceptEdits / bypassPermissions behave identically for Copilot.** Copilot exposes no MCP-style approval hook for overcli to broker, so non-Plan modes all map to `--allow-all-tools`. Plan mode narrows to read-only tools (`view`, `glob`, `grep`).
