# Changelog

All notable changes to Overcli are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [0.14.1] - 2026-08-13

### Added
- **A scheduled orchestration can launch a capped number of its own proposals.** Scheduled batches always parked: the producer investigated overnight and every candidate sat waiting for a click. That is still the default, but for a schedule whose producer you have learned to trust it means the useful half of the work waits on you. `autoApprove` opts out of the waiting and not out of the bound — the hazard was never "a scheduled batch launched", it was "the producer decided at 3am that there were thirty things to do", so the cap is required rather than optional and `maxConcurrent` does not do this job (it limits how many run at once, not how much work is committed to). The first N candidates queue in producer order, which is best-first by construction; everything past the cap stays proposed with a note saying why, so an unexpectedly large morning degrades into an ordinary parked batch instead of a dozen unsupervised worktrees. The cap is clamped in the engine as well as validated at save time, so a schedule written by an older build or hand-edited on disk cannot talk it into an unbounded dispatch ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **The Orchestrator has an idle stage.** Three numbered panes were sized for the ten minutes you spend composing a batch and wrong for the hours afterwards: Ask and Map sat empty while the ledger — the only thing with anything in it — was squeezed into a third of the width. The tab now has two modes. Composing keeps ①②③ and the split screen; idle shrinks Ask to a one-line launcher, drops Map, and gives the runs the full stage with a header of their own. The step numbers go with it, because nothing is mid-sequence there. Every count in the new runs bar is a filter, since a number you cannot act on is a run row given up for decoration, and clearing the finished two thirds of a busy ledger is the biggest thing that bar can do for the runs you actually came to watch. A batch awaiting approval renders whole regardless of the filter — an obligation is not a list entry — and a half-launched batch says how many already went, so "Discard the rest" declines the parked items instead of aborting live worktrees ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **A retried flow step is told why it was sent back.** `on_fail.goto` re-ran its target with only the inputs that step was authored with — a build step declaring `plan.md` got `plan.md` again and never saw the `review.md` that had just rejected it. So it produced the same work, got rejected again, and burned the entire retry budget doing it. The retry now leads with what happened: who rejected it, the verdict in one line, which attempt this is, and the rejecting step's artifact fed in even though no flow author could have declared an input that does not exist yet. The same notice shows in the step header, so the loop is visible in the run pane rather than looking like a step that inexplicably ran twice ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **The schedule editor is rebuilt on the flow editor's skeleton, with a fourth starter.** Same header, two-column body, card sections and save-at-the-top: these are the two places in the app where you build a thing rather than run one, and they were shaped differently for no reason a user could see. Save moving up matters on its own — on a tall schedule you had to scroll past everything you had just decided in order to commit it. The new starter answers Slack questions hourly through the working day, and it is the first one that repeats on an interval and the first that makes no worktree: it reads code to answer and writes to Slack, so forking the repo nine times a day would leave a trail of empty branches. Its prompt tells it to leave anything it cannot answer confidently alone, because an unattended run that guesses in public is worse than one that does nothing ([#139](https://github.com/overcodelions/overcli/pull/139)).

### Fixed
- **Effort levels reach the Claude CLI instead of killing the turn.** The flag was sent as `--thinking-effort`, which has never been a real option, so every send with a non-default effort level died on the spot with `error: unknown option`. The real flag is `--effort`, and older CLIs reject that one just as hard — hence the probe: the flag is dropped unless the installed binary advertises it, cached per binary path ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **A long producer turn is budgeted on silence, not a wall clock.** A producer that searches two issue trackers and diffs three repos does dozens of MCP round-trips, and the flat five-minute ceiling killed healthy runs mid-investigation — a schedule spanning several sources failed every single morning with "Timed out after 300s." A wall clock cannot tell "wedged" from "busy": raise it and a hung turn sits there, lower it and honest work dies. The budget now keys off idleness, resetting on every streamed event including tool-only batches, which is what a long investigation actually consists of, with a far-off absolute ceiling still behind it ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **A scheduled workspace run gets its worktrees.** A workspace root is not itself a git repo, but a run targeting one mints a worktree per member. The scheduler asked git about the root and nothing else, so every scheduled workspace run silently downgraded from `worktree` to `cwd` — unattended edits landing straight in the checked-out tree, which is the exact thing choosing a worktree is meant to prevent. The editor made the same mistake in the other direction, greying out "Fresh worktree" for a workspace and quietly pinning it to the working tree ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **Flow run rows have a fill again.** `bg-card/40` is an opacity modifier on a CSS-variable colour, which compiles to nothing — so every row in Active and Recent rendered as a bare outline with no background at all, which is why they read as all border and no substance. Named blends replace them, with no border, and a live run gets a faint accent wash rather than a coloured edge ([#139](https://github.com/overcodelions/overcli/pull/139)).
- **The flow library is ordered by the name you see.** Flows arrived sorted by id, which is the filename on disk and is renamed independently of the flow's name — so the list looked alphabetical right up until someone renamed a flow without renaming its file. Every surface that takes this order as given (the schedule editor's picker, the Orchestrator's per-candidate select, the library's own groups) now gets it sorted by the string it renders ([#139](https://github.com/overcodelions/overcli/pull/139)).

### Changed
- **The Gemini catalog moves to the 3.x line.** 2.5 Pro and 2.5 Flash were the entire list and both are a generation behind. Flash iterates faster than Pro — 3.7 Flash is out while 3.1 Pro is still the newest Pro id — so Pro stays first and remains the auto-pick and drafter default, with Flash and Flash-Lite behind it. The split gives the backend a real middle tier for the first time, so a drafted flow asking for a cheaper critic step finally gets one instead of degrading upward onto the strongest model available. Retired 2.5 ids keep their tier markers so a conversation still pinned to one renders correctly until it is moved forward ([#139](https://github.com/overcodelions/overcli/pull/139)).

## [0.14.0] - 2026-08-12

### Added
- **⌘K searches everything, not just conversations.** The palette only ever indexed chats, so anything that wasn't a conversation — a flow, a run, a project, a workspace — could be found only by knowing which tab it lived behind, which is the opposite of what a quick switcher is for. It now spans chats, agents, runs, flows, projects, workspaces, archived threads and app actions from one input. The ranking lives in a pure module with its own tests, because "an exact project name should beat a chat that merely contains the word" is the kind of rule that degrades silently — a test catches it and a screenshot doesn't ([#137](https://github.com/overcodelions/overcli/pull/137)).
- **The flow library is grouped by provenance, and its search spans the registry.** Once you'd installed a handful of flows the library was a flat alphabetical list, so the two flows you wrote yourself were the hardest things in it to find. Flows now sit under starred / yours / this project / installed, and the search box reaches the registry as well as what's on disk. When nothing matches anywhere the search text becomes the brief for an AI draft, which opens in the editor rather than running unseen — a flow nobody has read is not one to turn loose on a project ([#137](https://github.com/overcodelions/overcli/pull/137)).
- **A launch panel that says what a flow will do before it runs.** A flow an AI has just drafted is one you've never read, and launching it both saves it and turns it loose on your project. Drafts now spell out their pipeline up front, including whether any step can touch your working tree ([#137](https://github.com/overcodelions/overcli/pull/137)).
- **The start page's flow row is a real gallery.** It listed the first four flows you had, which past four flows is a random sample. It now carries the same grouping, search and registry results as the library, so you can pick a flow without leaving the start page ([#137](https://github.com/overcodelions/overcli/pull/137)).
- **Flows carry tags, from YAML through the drafter to the editor.** The registry already published tags; local flows had nowhere to keep them. Untagged flows stay byte-identical through a load/save cycle, so committed `.overcli/flows` don't churn on upgrade ([#137](https://github.com/overcodelions/overcli/pull/137)).
- **A first run that holds up when no CLI is installed.** The empty start screen decided what to show before it knew anything — `noBackendReady()` is false until the first health probe returns, so the opening frame was the happy path, which then rearranged itself once the probe landed: an amber box shoved in above the feature cards, the button greyed out, the sidebar gone. The first thing a new user saw was the app changing its mind. "Checking" is now a state of its own, so the first frame never claims something it hasn't verified. The setup card reads as an onboarding step rather than a list of npm commands, and backends you've disabled in settings are left out of it — telling someone to `npm install -g` something they deliberately turned off is noise. Installed-but-signed-out is treated as the near-win it is: those rows sort first, the headline becomes "Sign in to Claude to get started", and the row carries a Sign in button. And the screen watches — it re-probes every 4s while focused, and immediately on window focus, so installing a CLI in a terminal unblocks the app without a restart ([#138](https://github.com/overcodelions/overcli/pull/138)).

### Fixed
- **New conversations open on a backend that is actually installed.** The default was the first *enabled* backend rather than the first *ready* one, and with shipping defaults that is always `claude`. A machine with only Codex installed could clear onboarding, open every conversation on a CLI that wasn't there, and fail on the first send. `pickDefaultBackend` now prefers the first backend that is both enabled and ready. An explicit preference still wins — a health probe is not grounds to override what someone asked for — and enabled-order remains the fallback when health is unprobed or nothing is ready. The composer's backend pill seeds the same way and now labels its options "Not installed" / "Installed, signed out", so you see the problem while choosing rather than after the send fails ([#138](https://github.com/overcodelions/overcli/pull/138)).
- **A missing model tier degrades downward, not up to the priciest.** The drafter spends its `standard` hint on rebound critics and cheaper steps, but a backend with no standard model fell back to the *thinking* pick — so every critic loop in every Claude- or Gemini-drafted flow quietly ran on Opus or 2.5-pro. Neither backend has a standard model today, which made this the common path rather than an edge case ([#137](https://github.com/overcodelions/overcli/pull/137)).
- **Deleting a flow cleans up after itself, and only after its own file.** A delete left the flow's registry bookkeeping behind, leaving it both wrongly marked installed and impossible to reinstall, and the browse modal compounded it by remembering installs only from the current session — so it re-offered "Install" for flows you already had. The first cleanup then reached too far the other way: deleting a project-layer flow dropped the installed-registry entry for a same-named file in the *user* layer, which is a different file entirely. It is now scoped to user-layer deletes ([#137](https://github.com/overcodelions/overcli/pull/137), [#138](https://github.com/overcodelions/overcli/pull/138)).
- **Registry index fetches collapse instead of firing per keystroke.** The library and start-page search boxes both call `browseRegistries` from an effect guarded on `registryLoaded`, which only flips once a fetch *resolves* — so typing a query fired one index fetch per character. Unforced callers now join the in-flight promise, cleared on settle so a failed fetch cannot wedge the search box on "loading". A forced refresh still always goes to the network ([#138](https://github.com/overcodelions/overcli/pull/138)).

### Changed
- Dependency bumps: `marked` 18.0.3 → 18.0.5, plus CI-only moves to `actions/checkout` v7 and `github/codeql-action/upload-sarif` v4.37.0 ([#46](https://github.com/overcodelions/overcli/pull/46), [#110](https://github.com/overcodelions/overcli/pull/110), [#111](https://github.com/overcodelions/overcli/pull/111)).

## [0.13.4] - 2026-08-08

### Fixed
- **The file explorer keeps up with the agents writing into it.** The tree listed its root once per mount, so a file an agent dropped into the project simply wasn't there until you closed the pane and reopened it — the one view whose whole job is telling you what exists was the last to know. A recursive watcher per root lets the renderer relist itself as the tree changes underneath. The walk behind it is now two functions rather than one: a sync form for callers already on a blocking path, and an async one for the tree, which relists on every agent write and would otherwise stall the main process to do it ([#136](https://github.com/overcodelions/overcli/pull/136)).
- **Worktrees that outlived their work have an exit ramp.** Worktrees are deliberately long-lived — a conversation keeps its tree so you can reopen the chat and carry on — but nothing ever removed one when the work was genuinely finished, and two paths orphaned them outright: `pruneOldRuns` evicts a run's metadata without touching the worktrees that run recorded, and a failed removal left the tree on disk with nothing pointing at it. A sweep now finds the trees nothing references any more and offers them up. It surfaces as two Settings panes rather than one, and the split is the point: **Storage** reclaims disk and is scoped to orphans, while **Conversations** deletes history. They look similar enough to merge — both are cleanup, both key off worktrees — but the trade runs opposite. The conversations are typically kilobytes each, so folding them into a disk pane would have meant offering to destroy hundreds of chats in exchange for no measurable space ([#136](https://github.com/overcodelions/overcli/pull/136)).

## [0.13.3] - 2026-08-08

### Fixed
- **A flow step's rebound critic gets the number of rounds you asked for.** `max_iters` is a step's round budget for its critic, but the runtime never handed it over — it passed the critic's backend, mode, model and persona and stopped there, so the budget fell back to the interactive default of three. A step asking for one round got three, and a step asking for five also got three. It now goes through as the cap the runner already enforces on a critic's ping-pong. The setting was also documented as a general cap when it isn't one: `review` mode fixes its own count — round one always, round two only when the step actually changed code, never a third — so a step that writes markdown rather than code can't get past the first round whatever the budget says. That made a design or research step configured for `review` look like it would iterate when it structurally couldn't; the answer is `collab`, which is where the budget applies. Documented rather than changed, since the two-round rule is deliberate — it exists so a reviewer can confirm a fix landed without opening an unbounded loop ([#135](https://github.com/overcodelions/overcli/pull/135)).

## [0.13.2] - 2026-08-03

### Fixed
- **Conversations you're done with stop holding a CLI open.** `claude -p --input-format stream-json` stays resident for as long as its stdin is open, and it brings every configured MCP server with it, so a session costs its full footprint from the first message until the app quits. Nothing reclaimed that: archiving or deleting a conversation dropped the row and left the process behind, and a finished turn reports `isRunning: false`, so it was invisible to the running indicator and to every "stop it first" path in the UI. A measured session is about 1 GB across roughly fifteen processes — the CLI itself is under half of it, and the rest is the MCP servers it started, which sit two levels down (`claude` → `npm exec @modelcontextprotocol/server-x` → the server proper). Thirty of those parked is tens of gigabytes, and one machine was carrying a session whose conversation had already been deleted. Archive and delete now release the runtime, and a sweep retires any session idle past a timeout (Settings → Advanced → *Release idle sessions after*, 30 minutes by default, or Never). The sessionId is persisted, so the next message respawns and `--resume`s the same thread — the only cost is a slower first turn. The sweep declines in every case where teardown wouldn't be free: a turn still in flight, a permission prompt waiting on you, or a session with no sessionId to resume from, where reaping would be history loss wearing memory savings as a disguise. Archiving keeps its promise to be safe mid-turn and skips a busy session rather than cutting it short.

## [0.13.1] - 2026-08-02

### Fixed
- **Every open file is reachable once the tabs outrun the pane.** The strip scrolled horizontally with its scrollbar hidden, so past about eight files the rest were simply gone — no affordance said they existed, and the keyboard routes that could reach them (<kbd>⌘1</kbd>–<kbd>⌘9</kbd>, <kbd>⌥⌘←/→</kbd>) changed the selection without moving the strip, leaving you on a tab you couldn't see. The active tab now scrolls itself into view whenever it changes, including when the file is opened from the explorer rather than the strip. A pinned count button on the right opens the full list — file name, dimmed directory, the <kbd>⌘N</kbd> hint for the first nine, the unsaved dot and a close button per row — so the tabs that scrolled away stay one click from the front, and the count doubles as the answer to "how many files do I have open in here" ([#130](https://github.com/overcodelions/overcli/pull/130)).

## [0.13.0] - 2026-08-01

### Added
- **Scheduled runs.** A schedule is a trigger on work you already defined, not a new kind of run, so it lives as a segment inside Flows (Library | Schedules) rather than a fourth top-level tab that would have become a third place to launch from. The firing arithmetic is pure and testable: a schedule missed while the app was closed either coalesces into one catch-up run or is skipped, one that comes due mid-run can skip, queue a single follow-up or replace what's going, and editing a cadence re-anchors rather than firing on save. The engine holds one timer per schedule, re-derived from the nearest due time and capped at 60s, so a sleeping laptop or a stepped clock self-corrects instead of drifting. A worktree target against a directory that isn't a git repo degrades to the folder rather than failing preflight — plenty of scheduled work pulls data or talks to other systems and has no repo to fork — and where a repo does exist the isolation still applies. Every firing notifies natively, because unattended runs need a way out ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Scheduled proposals the orchestrator parks for approval.** The second target shape, and the asymmetry with the first is the design: *run a flow* launches one run with a fixed prompt, bounded and reviewable, while *propose a batch* runs the orchestrator's producer against your sources and **parks** what it finds. Every item lands `proposed` and nothing launches until you approve it. Dispatching a batch unattended is the one thing a schedule must not do — the producer decides how many items exist, so a bad morning would fork a dozen worktrees with nobody watching — and scheduling the investigation is the valuable half anyway. Parked batches surface inline on the schedule's own row, listing the asks rather than counting them, since "5 proposed" says a decision is waiting without saying whether it's a good one. Inline actions are Review & pick, Launch all and Discard; per-item approval deliberately stays in Orchestrator rather than growing a second copy that would drift ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Interval triggers take days and an active window.** "Every hour, weekdays, 8am–5pm" is the normal shape for a repeating check, not an exotic one — without a window you'd accept 24 runs a day to get the 9 you wanted, plus weekends. The arithmetic steps first and then checks, so a candidate outside the window jumps to the next opening instead of walking through the closed hours one interval at a time; that also re-phases each day to the window's start, so an 8–5 hourly schedule armed at 8:37 runs on the half hour today and from 8:00 sharp tomorrow. Both ends are inclusive, a start after the end wraps midnight, and the day set then applies to the side the window opened on. Validation rejects an interval longer than its own window, which would otherwise be a silent alias for "daily at 9"; an unparseable window degrades to no window rather than to one that never opens ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Scheduled activity in the title bar.** Scheduled work is now visible from whatever tab you're on, and one click from being opened. Three states in priority order: violet for a parked batch waiting on your approval, pulsing sky for a run going right now, green plus a countdown ("Scheduled · in 3h") for armed and idle. Waiting outranks running deliberately — one needs a human, the other just needs time — and shape carries the distinction as well as hue, filled for something happening, still for ready. The countdown is what proves an idle schedule is alive rather than forgotten, so the bar ticks every 30s, and only while something is armed. It renders nothing at all when no schedule is enabled: a permanently-lit item in the one strip that's always on screen is noise for people who don't use the feature and blunts the signal for people who do ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Scheduled runs are numbered so occurrences are tellable apart.** A run's title falls back to the first line of its prompt, and a scheduled prompt is fixed by definition, so every morning's run was titled identically and the library became a wall of the same sentence. Runs and parked batches now carry an `[SR-n]` prefix. *n* counts firings of that schedule rather than runs globally — two schedules will both have an SR-1, which is the trade, because "the 12th morning triage" is a fact about the schedule where a global counter would just be a serial number. Manual fires take a number too: they don't advance the cadence, but they do produce a real run in the same list ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **"What's new" after an update.** Updates installed silently on quit, so the app could change under you overnight with nothing to say what landed. Release notes now open once on the first launch after an update — not when the update downloads, since installation is deferred to quit and at that moment you're still running the old build. The notes come from this changelog, bundled into the app, rather than the GitHub release body, which is generated from PR titles. Someone who skips two versions gets both, newest first, capped at four with the remainder counted rather than silently dropped. A fresh install is stamped as current and shown nothing — nothing is "new" on your first launch — and the nightly channel is excluded, where a panel every launch would only teach you to dismiss it. Reachable any time from About, which now also reports the real running version instead of a hardcoded `0.1.0` ([#129](https://github.com/overcodelions/overcli/pull/129)).

### Changed
- **The Flows header segments are a real segmented control.** They were two bare words with a background on the active one, so the inactive half read as a subtitle to the heading next to it rather than as something clickable. There's a track now — a recessed surface so both halves read as options, with the selection a raised pill — and inactive text moves from faint to muted, since faint is the tone this codebase reserves for disabled and metadata. Schedules also announces itself once: a slow 2.4s breathe and a "new" pip that retire permanently after the first visit, because a highlight that never stops is one the eye learns to skip ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **The sidebar's Active section is ordered by what you last touched.** Liveness earned a slot *and* set the order, so every step a backend advanced re-sorted the list under your cursor, and over the cap a busy run could evict the chat you had just typed in. Membership and order are separate now: liveness still earns the slot, but rows sit where you left them ([#128](https://github.com/overcodelions/overcli/pull/128)).

### Fixed
- **A worktree run's changes list no longer counts upstream commits as its own work.** Diffs started from the fork point captured when the worktree was minted, which is exact on the day of the run and wrong forever after — once the branch takes upstream in via a pull, merge or rebase, every one of those commits reads as part of this branch's work. One run whose PR had already landed showed 199 changed files, all of them other people's merges. The base is resolved live now, from `merge-base(base, HEAD)`, preferring remote-tracking refs over a local branch nobody has fetched in a week. Merging upstream *into* the branch doesn't push that point past the branch's own commits, so in-flight work survives; once the work lands, the diff correctly collapses to nothing. The old frozen baseline stays as both last resort and floor, which is what keeps a worktree forked from another feature branch from dragging its parent's work into the diff ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Reopening a compacted conversation no longer shows the summary as something you typed.** Replay dropped the compaction boundary entirely and rendered the summary the CLI writes as an ordinary user message — 25k characters you appeared to have sent. Replay now emits the boundary notice and drops the summary, matching the live stream ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **Go to definition works in worktree runs and symlinked workspaces.** The renderer sent the conversation's root, which in those cases is not the tree the open file lives in, so the search found nothing. Resolution and validation now run against the file's own tree ([#128](https://github.com/overcodelions/overcli/pull/128)).
- **"Run now" no longer resets the cadence or double-launches.** A manual fire stamped `lastFiredAt` like a real occurrence, which for an interval trigger restarts the whole clock — checking an hourly schedule at 8:59 silently cost you the 9am run you were checking on. A test drive is not an occurrence, so it leaves the cadence exactly as it found it. Separately, nothing guarded the window between starting a run and the launch resolving: `activeRunId` isn't set until it returns, and a worktree checkout leaves seconds in which the schedule looks idle, so a double-click on Run now — or a tick landing mid-launch — started a second run. An explicit in-flight set covers it, and ticks skip those schedules outright ([#128](https://github.com/overcodelions/overcli/pull/128)).

## [0.12.0] - 2026-07-30

### Added
- **File editor tabs, remembered per conversation.** Opening a second file replaced the first, and every navigation — switching conversation, opening the explorer, changing flow run — threw the editor away entirely. Files now open as tabs: a new one lands to the right of the active tab so walking a call chain reads left to right, capped at 12 per scope and evicting the oldest *clean* tab (if everything is dirty it goes over the cap rather than discard work). Unsaved edits survive a tab switch — the text lives outside the store so keystrokes don't churn it, with only the dirty flag reactive for the strip's modified dot. Middle-click closes, <kbd>⌘1</kbd>–<kbd>⌘9</kbd> jumps, <kbd>⌥⌘←/→</kbd> cycles, and labels disambiguate to `main/index.ts` when two tabs share a name. Closing a tab confirms and discards; closing the pane keeps dirty buffers, so reopening the file brings the work back ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **Open files come back when you return.** Tabs are scoped per conversation, per flow run and per explorer root, replacing the five separate places that used to clear the editor on navigation. Leave a conversation and come back and your files are still open, in the same order, on the same tab — and they survive a restart. Only the paths and which tab was in front are persisted: view modes and jumped-to line ranges are per-session, and unsaved buffers deliberately never reach disk. Scopes for deleted conversations and files that have since left the tree are pruned on load, so a returning user doesn't get a strip of tabs that each say "this file was deleted" ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **Compact a conversation from the footer or the More menu.** The context meter told you the window was filling up; this puts the fix next to the number. Two-step arm/confirm, because compaction is irreversible and the button sits a few pixels from the composer of a running flow. The draft survives — sending clears the composer as a side effect, which is right for a typed message and wrong for a button, since the draft you'd want to keep is exactly the one you were writing when you noticed. Claude only (the other backends would take `/compact` as a literal prompt), and wired into flow runs on the participant's own resumed session, so freeing context there frees it for the step that comes next ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **The file tree is colour-coded by type.** Icons carry each language's own brand colour, with filled glyphs, a dot on test files, and drab greys for archives and binaries so the eye skips them. Whole-name matches beat extensions, so `package.json` doesn't look like a generic data file. Folders are tinted only when the name states a role — `src`, `test`, `dist`, `node_modules` — because tinting them all is a fruit salad. Every colour clears roughly 3:1 against both the light and dark surfaces ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **Open a folder in Terminal.** From the tree header for the root, or on hover for any folder row. Same containment rule as popping a conversation out to a terminal, plus a directory check, and a leading-dash path is refused rather than passed to `open` as a flag ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **Go to definition announces itself.** Nothing in the UI said the gesture existed — you had to already know that ⌘-click resolves a symbol. Holding ⌘ (Ctrl elsewhere) now underlines the identifier under the pointer and turns the cursor into a link, so the cue appears exactly when you could act on it, and doubles as a preview of which word a click would resolve. Only identifier-shaped words qualify, so hovering a numeric literal no longer promises a jump that comes back as an error. Also listed in the shortcuts sheet ([#126](https://github.com/overcodelions/overcli/pull/126)).

### Changed
- **Files open in the editor, not preview.** A README or a `.tsx` opening as a rendered page was rarely what you wanted, and with tabs it meant every file in the strip opening in a different mode. Preview is still one click away, and callers that genuinely mean it — or mean Diff — still ask for it explicitly ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **A jumped-to line range is much harder to miss.** The tint alone was easy to lose on a dense screen: you jump to line 412 of a 900-line file and have to hunt for where you landed. There are three cues now — a stronger wash, a solid accent bar down the left edge, and a one-shot flash on arrival that fades to the resting tint ([#126](https://github.com/overcodelions/overcli/pull/126)).

### Fixed
- **Clicking a symbol no longer stalls every running agent.** Go-to-definition ran ripgrep through `spawnSync` and read candidate files — up to 8MB, once per candidate — with `readFileSync`, on the thread that brokers every streaming IPC message from every agent. Both are async and bounded now; reading a candidate's line walks to that line and stops, so cost tracks the line's offset rather than the file's size. The tier order was backwards too: several grep candidates bought a model call, sometimes two at 25s apiece, to rank a list it already had — and then fell back to that list anyway when the model's answer didn't verify. Grep now answers immediately and the picker offers **Refine**, with the model tier running unasked only when grep found nothing. Failures cache briefly, so repeat clicks on an unresolvable symbol stop re-running the whole ladder ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **Dragging a pane divider no longer stutters on release.** Backend health probing executes every installed CLI, and saving settings refreshed health *and* the reviewer list — which probes all five backends again — on **every** settings write, including the one that persists a pane width. Releasing a divider drag ended in up to ten synchronous CLI spawns on the main thread. Probes are async now, with a short result cache and in-flight deduplication, and a settings write only re-probes when a binary path or an enabled flag actually moved; signing in stays responsive by forcing a fresh probe. The drag itself also re-rendered the entire file tree and editor at pointer-move rate, which is now memoized away ([#126](https://github.com/overcodelions/overcli/pull/126)).
- **The context meter no longer overstates occupancy.** It folded in aggregated usage totals; only per-message `usage` blocks measure a single window, so those are all that count now ([#126](https://github.com/overcodelions/overcli/pull/126)).

## [0.11.0] - 2026-07-30

### Added
- **Context-window occupancy in the footer.** The only warning that a conversation was filling its window used to be the model itself mentioning it — by which point a long flow step had been degrading for a while. The footer now shows occupancy (input + cache reads + cache creation from the most recent request, i.e. the floor for what the next request resends), amber past 60% and red past 85%. Subagent usage is excluded, since a Task runs its own window; the denominator comes from the CLI's reported `contextWindow`, and without one the raw count is shown rather than an invented percentage. Reopening a conversation seeds the meter off the replayed transcript, and flow runs get the same readout per participant — participants keep one conversation across every step they run, so that number climbs quietly over a long flow ([#125](https://github.com/overcodelions/overcli/pull/125)).
- **Cmd-click go to definition in the file editor.** Cmd-click (Ctrl elsewhere) an identifier to jump to its definition, with a picker when more than one site is plausible. Resolution is two tiers, cheapest first: ripgrep declaration patterns (~10ms, zero tokens, and enough for most symbols), then a one-shot query on the cheapest fast model when grep is ambiguous or empty. Every candidate is verified against disk before it reaches the renderer — the path must resolve inside the project root, the line must exist, and the line must mention the symbol — which is what makes the cheap model tier safe: a wrong `path:line` fails the check and escalates a rung instead of navigating somewhere wrong. The lookup runs entirely off the conversation, so clicking a symbol never perturbs the agent's context ([#125](https://github.com/overcodelions/overcli/pull/125)).
- **Rename runs and flows in place.** Runs were identified only by the first line of their prompt, and fixing a badly-named flow meant a trip through the full editor. Runs now carry an optional title, editable by double-clicking a sidebar row or the run headline, at any point in a run's life including mid-step. Flows rename from the library row. A rename touches the display name only — the id, and therefore the file on disk, the star key, and every recorded run's `flowId`, is left alone, so it can never orphan anything ([#125](https://github.com/overcodelions/overcli/pull/125)).
- **"Run flows in a worktree by default" setting.** The launcher's run-in toggle reset to the project tree on every launch, so a worktree-first user re-flipped it every time. Settings → Flows now seeds it, for both the start page's flow row and the library launcher; the per-run toggle still wins ([#125](https://github.com/overcodelions/overcli/pull/125)).
- **Compaction is reported as it happens.** The notice carried no numbers and arrived only after the fact, and two states never surfaced at all: the ~20s stall while a large transcript is summarized, and a compaction that *failed* — which the CLI reports on a line overcli dropped, so a manual `/compact` could silently do nothing. Boundaries now read like "Conversation auto-compacted · 180k → 42k tokens", and only claim "auto" when the CLI said so ([#125](https://github.com/overcodelions/overcli/pull/125)).

### Fixed
- **The UI no longer locks up while several agents stream.** Two causes, both on hot paths. Persisting the store serialized every project, workspace and conversation — pretty-printed — synchronously on the main-process thread, which is also what brokers every streaming IPC message from every running agent; a few agents finishing turns at once stalled the whole window. Writes now coalesce over a 500ms window and run off-thread, keeping the atomic tmp+rename, with a synchronous flush on quit and a write-generation guard so an in-flight write can't clobber a newer snapshot. Turn completion — the most frequent write, and one that only moves a scalar — goes through a new targeted `store:patchConversation` instead of cloning the whole tree across IPC. Separately, the sidebar, conversation header and flow-run rows subscribed to the full runners map, whose identity changes on every ingested event, so they re-rendered at the streaming rate (~60Hz for the duration of every turn) while re-running unmemoized filters over every conversation in the app; they now read a value-compared projection of just the fields they use ([#125](https://github.com/overcodelions/overcli/pull/125)).
- **Saving an existing flow no longer forks a user copy of a project flow.** The editor's target defaulted to the user layer regardless of where the flow came from. It now defaults to the flow's own layer, and changing a flow's id properly moves the file — previously the new file was written and the old one left behind, so the library showed the flow twice — carrying the star over to the new key. Saving into the *other* layer is still treated as a copy and deletes nothing ([#125](https://github.com/overcodelions/overcli/pull/125)).
- **The expanded changes list scrolls instead of pushing the composer off-screen** on runs that touched dozens of files ([#125](https://github.com/overcodelions/overcli/pull/125)).
- **Dev userData no longer grows without bound.** Vite's HMR appends a fresh cache-busting query to every module on every edit, and Chromium treats each as a new permanently-cacheable URL; months of dev had accumulated ~32k entries and 1.6GB. The dev HTTP and code caches are now cleared on launch. Production loads from `file://` and was never affected ([#125](https://github.com/overcodelions/overcli/pull/125)).

Chats, agents and flow runs compete for the same slots instead of flows sitting on top with a separate cap; hidden conversations and archived runs are excluded from the backfill. The changes bar strikes through deleted paths and keeps them clickable ([#113](https://github.com/overcodelions/overcli/pull/113)).

### Fixed
- **Running indicators self-heal instead of spinning forever.** The indicator is edge-triggered, and a run's liveness ORs in its conversations, so one lost `running: false` made a *finished* flow run read as still working — one held a sidebar spinner for 13 hours. Three defences: a conservative main-side sweep that retracts only when nothing can still speak for the conversation (silence alone is never enough — a long tool call is quiet for minutes), a 10-minute ceiling on reviewer rounds, and a renderer reconcile that polls main's authoritative busy set and clears local flags absent from it ([#122](https://github.com/overcodelions/overcli/pull/122)).
- **Flow runs no longer wedge permanently on a single step.** A step with no assigned participant filed its conversation under its own id but was looked up under a blank key, so its own completion event was discarded and the run waited forever for something it had already thrown away. Separately, a step whose backend died quietly had no path out of `running` at all. Steps silent for over 30 minutes now fail into the same recoverable pause a rejected step gets ([#122](https://github.com/overcodelions/overcli/pull/122)).
- **Flow steps no longer fail off a superseded process's close.** When a conversation's process is killed to apply changed launch params, it drains asynchronously while a replacement turn is already live; the dead process's late `running:false` was mistaken for the new step finishing ("produced no `<output>`") ([#115](https://github.com/overcodelions/overcli/pull/115)).
- **The app returns to what you were looking at after sleep.** Only the selected conversation was persisted, so a renderer re-init — macOS discards the render process during a long sleep — dropped you off any flow run, orchestrator batch or project welcome screen back to the default view. The full view identity is now persisted and restored ([#116](https://github.com/overcodelions/overcli/pull/116)).
- **The orchestrator's main-tree choice survives a reload.** The `runIn` toggle lived only in the renderer store, whose fresh default is `worktree`, so after a reload a batch you'd set to main tree silently went back to worktrees. The sticky batch-launch defaults are now persisted alongside the view ([#117](https://github.com/overcodelions/overcli/pull/117)).
- **Two new flows no longer overwrite each other.** A flow's id becomes its filename, and every blank flow started as the constant `new-flow`, so the second silently replaced the first. New flows get a collision-free id; editing an existing flow keeps its id ([#118](https://github.com/overcodelions/overcli/pull/118)).
- **An unknown step role fails validation instead of running "undefined".** A role that is neither a preset nor `custom` resolved to the literal system prompt `"undefined"` — a silent runtime failure ([#118](https://github.com/overcodelions/overcli/pull/118)).
- **Codex tool output that arrives as content blocks no longer breaks history.** Codex now writes `function_call_output.output` as an array of content blocks; the field is typed `string`, so an array poisoned every consumer that trusted the type and broke `runner:loadHistory` in the dedupe path ([#122](https://github.com/overcodelions/overcli/pull/122)).
- **Queued workspace context notices stay bounded.** Workspace edits queue a notice onto every conversation, cleared only when that conversation next sends — so one you never send to again accumulated them forever. One real workspace had 103 stacked notices (52 KB) on a single conversation, which would have prepended ~13k tokens of stale churn to its next message. Resuming a session from the terminal also dropped its model ([#113](https://github.com/overcodelions/overcli/pull/113)).

The catalog now installs the managed endpoint through a pinned `mcp-proxy-for-aws`, with the default region carried in `--metadata` rather than `env` (the managed server reads its region from proxy metadata, so the old env var silently stopped meaning what it meant). ## [0.4.0] - 2026-06-28

The Orchestrator: fan a backlog out into a batch of flow runs, one git worktree per ask. Plus paused-run durability, snappier flow launches, and a security dependency sweep.

### Added
- **Orchestrator — batch fan-out of flows.** A new tab turns a source of requests (product feedback, tickets, a backlog — reached through your connected MCP tools) into a list of small, self-contained asks, maps each to a flow, and launches them together under a concurrency cap, one git worktree per ask. The producer turn investigates read-only and emits a candidate list you can triage and remap before launching, and each batch persists as a ledger ("why did I launch these?") across restarts ([#88](https://github.com/overcodelions/overcli/pull/88)).
- **Recent producer prompts.** The Orchestrator's Ask pane remembers the prompts you start fresh asks with and offers the most recent as one-click starters, so a good backlog query is re-runnable without retyping. Refinements are never recorded (they're meaningless out of context), and the list is deduped, capped, and persisted globally across projects ([#92](https://github.com/overcodelions/overcli/pull/92)).

### Changed
- **Launching a flow no longer freezes the app.** Worktree creation for a new run now happens asynchronously, so kicking off a flow — or a whole batch — keeps the UI responsive instead of blocking on git ([#89](https://github.com/overcodelions/overcli/pull/89)).

### Fixed
- **Paused flow runs stay paused across an app restart** instead of being demoted or silently resumed, so a human checkpoint survives a relaunch ([#90](https://github.com/overcodelions/overcli/pull/90)).
- **Opening a flow run no longer duplicates its chat,** and opening runs is faster ([#91](https://github.com/overcodelions/overcli/pull/91)).

### Security
- **Patched vulnerable dependencies to clear every open Dependabot alert (16 → 0).** `dompurify` — the renderer's HTML sanitizer — was bumped to 3.4.11; `hono`, `shell-quote`, `form-data`, and `tar` were forced to patched versions via npm `overrides`, and regenerating the lockfile cleared four further dev-tooling advisories (babel/core, joi, js-yaml, vite) ([#93](https://github.com/overcodelions/overcli/pull/93)).

## [0.3.1] - 2026-06-09

A bugfix release that makes packaged Claude usable again, plus the Fable 5 model.

### Fixed
- **Packaged builds spawned a fresh Overcli window on every Claude message turn**, making the app unusable. The `runAsNode` Electron fuse was disabled, so packaged binaries silently ignored `ELECTRON_RUN_AS_NODE` and booted a full GUI instance instead of running the Claude permission-broker helper headlessly as Node. Re-enabled the fuse (entitlements already permit it under hardened runtime) and documented the coupling at the helper spawn site so it isn't hardened back off ([#85](https://github.com/overcodelions/overcli/pull/85)).

### Added
- **Claude Fable 5 (`claude-fable-5`)** added to the model catalog as a new top `frontier` tier. The default Claude model is now **Opus 4.8**, and the bundled flow templates' planning steps (`plan` / `design`) use Fable 5, degrading to the backend's `thinking` model where Fable isn't available. Also salvages AI-drafted flows that named a near-miss model id (e.g. `claude-haiku-4.5` → `claude-haiku-4-5`) before validation ([#86](https://github.com/overcodelions/overcli/pull/86)).

## [0.2.0] - 2026-06-06

The biggest release since the project went public: a full multi-agent **Flows** system, a fifth backend (**GitHub Copilot**), in-app **auto-updates**, a curated **MCP catalog**, and a lot of polish.

### Added

**Flows — multi-agent pipelines**
- Visual flow builder + YAML flow library + run UI: chain steps across models, hand off artifacts (`plan.md` → `diff` → `review.md`), add retry edges, and tune each step's role, tools, and checkpoints ([#28](https://github.com/overcodelions/overcli/pull/28)).
- Per-step diffs, launch attachments, and richer step cards ([#31](https://github.com/overcodelions/overcli/pull/31)); live Workflow progress with gated reviewer steps ([#58](https://github.com/overcodelions/overcli/pull/58)).
- Post-completion **watch** mode — keeps an agent on a finished run to answer follow-ups, with readable per-tick summaries ([#68](https://github.com/overcodelions/overcli/pull/68), [#71](https://github.com/overcodelions/overcli/pull/71)).
- Flow starring and a smoother Continue flow; finished runs stay in the sidebar's Active set ([#42](https://github.com/overcodelions/overcli/pull/42), [#53](https://github.com/overcodelions/overcli/pull/53)).
- Workspace worktrees for flows and human-readable flow branch names ([#41](https://github.com/overcodelions/overcli/pull/41), [#73](https://github.com/overcodelions/overcli/pull/73)).

**Backends & models**
- GitHub Copilot CLI as a **fifth backend** — streams the JSONL event protocol, renders tool calls (view / edit / create / bash / glob / grep) as canonical tool cards, replays history from `~/.copilot/session-state/<id>/events.jsonl`, and resumes via `--resume`. Includes a health probe (binary auto-discovery, `COPILOT_GITHUB_TOKEN` / `GH_TOKEN` / `GITHUB_TOKEN` detection) and Settings → Backends/Models entries ([#20](https://github.com/overcodelions/overcli/pull/20)).
- Copilot as a rebound-review primary — `same`-backend presets auto-route to Claude / Codex / Gemini with a "Routed via X" chip in the popover.
- Claude **Opus 4.8** support ([#44](https://github.com/overcodelions/overcli/pull/44)) and an experimental Claude Agent SDK transport ([#10](https://github.com/overcodelions/overcli/pull/10)).
- More reliable Ollama tool calling (incl. Gemma 12B+) and rebound reviewers that can `read_file` / `list_dir` / `grep` ([#18](https://github.com/overcodelions/overcli/pull/18), [#22](https://github.com/overcodelions/overcli/pull/22), [#27](https://github.com/overcodelions/overcli/pull/27)).

**Updates & extensions**
- In-app **auto-update** with stable + nightly channels ([#64](https://github.com/overcodelions/overcli/pull/64)); update the Codex CLI via a hidden npm install with a terminal fallback ([#60](https://github.com/overcodelions/overcli/pull/60)).
- Curated **MCP catalog** with one-click install per CLI, plus bulk-add and copy-to-all in the Extensions browser ([#57](https://github.com/overcodelions/overcli/pull/57), [#59](https://github.com/overcodelions/overcli/pull/59)).

**Workflow & UI**
- Sub-agents (Task/Agent) surfaced with an inline card + drawer ([#25](https://github.com/overcodelions/overcli/pull/25)).
- Side-by-side explorer for folders and Explore ([#15](https://github.com/overcodelions/overcli/pull/15)).
- All-time usage stats alongside the rolling 5h / 24h / 7d view ([#73](https://github.com/overcodelions/overcli/pull/73)).
- Structured diagnostics session logger with file output ([#37](https://github.com/overcodelions/overcli/pull/37)).
- Plan mode: `ExitPlanMode` gated through the permission broker so approval works ([#62](https://github.com/overcodelions/overcli/pull/62)); broker resilience + MCP debug logging ([#61](https://github.com/overcodelions/overcli/pull/61)).
- Running indicator pinned above the composer ([#63](https://github.com/overcodelions/overcli/pull/63)).

### Fixed
- Flow watch "detect" ticks no longer run on Haiku — any Haiku-named model is filtered out of the detect ladder, so the cheapest rung is Sonnet for Claude (Codex `mini` / Gemini `flash` unaffected). Haiku proved unreliable at the mechanical detect job ([#75](https://github.com/overcodelions/overcli/pull/75)).
- Flows reliability: watcher answers questions dependably and loads deferred MCP tools, no duplicate step execution after Continue, finalize conversation drains before advancing, light-mode card colors, and Ollama-only preflight allowlist ([#43](https://github.com/overcodelions/overcli/pull/43), [#45](https://github.com/overcodelions/overcli/pull/45), [#56](https://github.com/overcodelions/overcli/pull/56), [#69](https://github.com/overcodelions/overcli/pull/69), [#70](https://github.com/overcodelions/overcli/pull/70), [#72](https://github.com/overcodelions/overcli/pull/72)).
- Missing/unresolvable backend CLIs now surface a clear error instead of hanging the turn or crashing the main process.
- Removing an agent no longer silently force-deletes a branch with unmerged commits — it warns and points to reflog recovery.
- Ollama bubble theming (amber, not Claude purple) and a clearer empty-`AskUserQuestion` message ([#16](https://github.com/overcodelions/overcli/pull/16), [#26](https://github.com/overcodelions/overcli/pull/26)).

### Changed
- Markdown re-parses throttled to ~12 fps during streaming for smoother output ([#11](https://github.com/overcodelions/overcli/pull/11)).
- Dropped the full-viewport backdrop blur on modal overlays — snappier modals ([#39](https://github.com/overcodelions/overcli/pull/39)).
- Dead-code cleanup and de-duplication across the codebase ([#54](https://github.com/overcodelions/overcli/pull/54)).
- macOS builds target arm64 (Apple Silicon); download docs corrected to match.

### Security
- Disabled the `runAsNode` Electron fuse (defense in depth).
- Overrode `qs` to patch a ReDoS/DoS ([GHSA-q8mj-m7cp-5q26](https://github.com/overcodelions/overcli/pull/38)) and bumped DOMPurify ([#35](https://github.com/overcodelions/overcli/pull/35)).

### Known limitations
- **Copilot as a reviewer backend is not supported.** Copilot's CLI takes prompts in argv, but the reviewer plumbing feeds prompts via stdin. Copilot is hidden from the reviewer picker.
- **Collab-mode rebound is disabled when Copilot is the primary.** Copilot exits after each turn, so the runner can't push reviewer pingbacks into it. Greyed out in the popover with an explanation. Tracked in [#19](https://github.com/overcodelions/overcli/issues/19).
- **Permission modes default / acceptEdits / bypassPermissions behave identically for Copilot.** Copilot exposes no MCP-style approval hook for overcli to broker, so non-Plan modes all map to `--allow-all-tools`. Plan mode narrows to read-only tools (`view`, `glob`, `grep`).

## [0.1.0] - 2026-05-09

Initial public release.

### Added
- Multi-backend chat for Claude, Codex, Gemini, and Ollama with a unified streaming UI.
- Workspaces (projects-of-projects) so a single conversation spans multiple repos.
- Silent background agents (doc-writer, PR-reviewer).
- Rebound reviews — fire a second agent, optionally on a different backend, after each turn; collaboration mode loops until the reviewer is quiet.
- Tool cards for file edits (inline diffs), bash, reads, writes, todos.
- Claude permission prompts and Codex approval cards rendered as proper UI.
- History loaded from `~/.claude/projects`, `~/.codex/sessions`, `~/.gemini/tmp`.
- Built-in file editor with syntax highlighting and HTML/Markdown previews.
- Extensions browser unifying slash commands, sub-agents, skills, plugins, and MCP servers across backends.
- Agent worktrees: create, update, rebase, merge, push, or remove from inside the conversation.
- Live changes bar above the composer with `+/−` rollup for the current turn.
- Local model dashboard for Ollama (catalog, pull/delete, server logs, GPU readout).
- Usage dashboard with rolling 5h / 24h / 7d stats.
- Smart downgrades near rate or cost caps (off by default).
- Per-backend health badges.
- Colosseum: same prompt against every backend in parallel git worktrees.
- Cross-platform packaging via electron-builder (macOS dmg/zip, Windows NSIS, Linux AppImage/deb).
